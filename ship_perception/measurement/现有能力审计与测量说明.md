# V1.5-R0 现有能力审计与测量说明

本目录是离线诊断代码，不属于 R1 产品链。原始 PCD、弱标注、Oracle ROI、原始候选和逐点横断面只写入被 Git 忽略的 `Ship-Unloader-Work/`。旧 `hold_detector` 只读；旧模型仅作为独立 Python provider 运行，产品代码不 include/link 它。

| 能力 | 判定 | 证据与复用边界 |
|---|---|---|
| PCD strict decoder | EXISTING / REUSABLE | `ship_perception/tools/v15_pcd.py::decode`；本轮所有 provider 均先走严格解码和 manifest SHA 校验。 |
| PLY decoder | LEGACY_ONLY | `Ship-Unloader-Data/legacy/hold_detector/detect/analyze_pcd.py::load_ply`；本轮冻结 Development 输入是 PCD，无需新写 PLY。 |
| 高度图 | EXISTING / REUSABLE | V1.5 `geometry_fit.cpp::height_grid`；旧 Python `analyze_pcd.py::build_grid` 作为诊断 provider 的只读实现。 |
| Connected components | EXISTING / REUSABLE | V1.5 `geometry_fit.cpp::find_openings`；诊断 provider 用相同粗网格和配置的 scipy 连通域，不改变产品。 |
| Geometry proposal | MISSING AS INDEPENDENT PROVIDER | 当前 `extract_structures` 在全链内部产生 opening，并不独立导出 NMS 前候选。本轮仅加最小低表面连通域诊断 provider，标 `GEOMETRY_MINIMAL`。 |

| NMS | LEGACY_ONLY / ADAPTED | 旧 `cnn_infer.cpp::detectWithCnn` 为 IoU>0.3、Top-5；本轮诊断副本保留被压候选及原因。 |
| Ring / Deck | EXISTING / REUSABLE | V1.5 `offline_ship_frame.cpp::detect_deck` 和旧 `cnn_infer.cpp::ringDeck`。Oracle 用局部粗 ROI 裁云后调用现有 `v15_recognize ship-frame`；额外局部 ring audit 不反馈产品。 |

## 运行与归因口径

```powershell
python -m unittest ship_perception.tests.test_v15r0_measurement -v
python -m ship_perception.measurement.run_proposals --data-root Ship-Unloader-Data/legacy/hold_detector
python -m ship_perception.measurement.run_oracle --data-root Ship-Unloader-Data/legacy/hold_detector
```

`run_proposals --scene-manifest <已裁定文件>` 才计算逐舱一对一粗框召回。粗重叠采用 axis-aligned envelope IoU≥0.1，覆盖两舱的一个大框不当作两次召回；这是 Proposal 诊断阈值，不是 15 cm 结构精度。`run_oracle --scene-manifest ... --recognizer <现有 v15_recognize>` 才裁剪粗 ROI、调用当前 C++ 几何核心和生成横断面审计。Oracle ROI 不进入 runtime proposal、产品配置或负样本挖掘。没有裁定的物理 opening-side 边证据时，不能从框 IoU、局部 plane 残差或候选数量声称 Oracle 成功。

当前报告中的 `null` 代表缺少可靠裁定依据，不代表 0%，也不允许据此判定 `PROPOSAL`、`LOCAL_GEOMETRY` 或 `BOTH`。多船 stress 在未有目标船区域与归属前只能标 `TARGET_ASSIGNMENT_UNRESOLVED`，不能假装自动选船。
