# V1.5-R1-S4-R2H-B4：高度拓扑与实测内沿融合复盘

## 边界与结论

本轮在 R2H-B3 `e8ae3cd1` 上做离线静态审查。输入是经过清单 SHA 校验的 Raw XYZ、R2G 矩形和 B2 逐船证据；旧图、旧标注及测试预期均不进入探测器。输出保存在被忽略的 `Ship-Unloader-Work/review/r2h_b4/`，不改变 V1.4 或 C++ Production 控制链。

结论是 **08-01 双舱的共同底边得到实测约束，4-16 和 7-16 的明显外扩边有所收敛；08-08 的四角能提供位置反证，但其两条横向边仍有平行模式冲突。静态内沿准确率未获独立 Golden 验证，不能宣称精准标定验收完成。** 所有 B4 输出是 `PARTIAL_HATCH` 或更保守状态；7-16 为 `UNRESOLVED` 复核几何。

## 历史能力复核

| 来源 | 已验证的价值 | 本轮采用方式 | 不继承的假设 |
| --- | --- | --- | --- |
| 旧 `hold_detector/detect/analyze_pcd.py` | 每条边检查内外环带；无数据与反证分开 | 保留逐边开口关系、支持比例和可缺边状态，结合 Raw3D/BEV 实测线 | 固定最小长宽、把高度环带当钢边 |
| 旧 `hold_detector/detect/train.py` | 逐边收缩/扩张；凹坑和高料都可成为内部线索 | 相对周边中位高度判断低盆地或高料，逐边移动且可回退 | CNN 权重、固定窗口、物料高度即钢边 |
| R1-S3 高度图 `c21307e` | 0.5 m 中位高度、跨层区域和局部四侧上升可找粗区域 | 复用 Raw XYZ 高度面，新增局部内外环带与四角对比诊断 | 最大连通域代表船、粗区域边等于舱口内沿 |
| R2F `0849844` | Raw3D、RawXYZ、Height 融合能形成初始矩形 | 保留初始矩形及四边方向 | 排序中早期面积/最小边长正奖励可导致外框偏置 |
| R2G `4f73c2b` 与 B3 `e8ae3cd` | 多截面连续 rho、未去重模式、冲突回退和同船弱宽度证据 | 只在 B2 线、局部高度过渡和船舶归属交叉支持时改边 | 单个更大模式可覆盖 B3 冲突；宽度先验凭空生成边 |
| R2H-B1/B2 | 多船假设与逐船结构线证据 | 逐船寻找侧边；允许相邻 `UNRESOLVED` 支持提供几何上下文，不读取另一条已确认船的线 | component 即船；跨船共用轴、宽度或支撑 |

R2F 去掉尺寸项的离线消融显示：7-16 的外框偏置可被证实，但直接删除尺寸排序后又会选中极小结构条带；因此不能用改一项分数代替边线角色判断。B4 以已存在矩形为初值，使用 B2 原始 provider 线做逐边复核。它没有解决 R2F 上游零候选的场景。

## 算法变化与可追溯性

`opening_semantics.py` 输出每条边的旧/新 rho、模式来源、Raw3D 与 BEV 覆盖、局部高度过渡、所属船假设及冲突原因。低料盆地与高料内部都可记录；高度和角点只是开口区域证据，不能单独确认为围板。四角在局部内外象限比较，随整体 Z 平移保持语义一致。B2 与 R2G 的轴只在旧外边明显弱时切换，避免全船局部轴无条件重定向。

08-01 两舱在 `V≈4.64 m` 独立观测到同一横向 Raw3D+BEV 线，而且各自测得内侧高度过渡；另一舱的远侧探针被遮挡时，由相邻舱提供额外观测。两舱共享横梁、上沿相近，等宽约束仅在已有共同实测线中消歧。右舱 V0 从约 2.01 m 移至 4.64 m，左舱从约 3.98 m 移至 4.64 m；旧宽度差约 1.8 m，新宽度差约 0.18 m。缺失任一舱的实际共边时，反例测试要求两边都不移动。输出仍是 `PARTIAL_HATCH`，未把邻近未确认支持晋级为确认钢边。

`opening_semantics_review.py` 生成每景五图：A 高度与相对内部、B 船体支持与候选边、C R2F 候选排序、D 逐边角色、E 原框白线与复核框琥珀线。JSON 保留每条边的所有候选模式；`reviewed_rectangles.ply` 可与点云在 CloudCompare 叠加，文件头明确标记未验证钢边。PNG/PLY 只用于人工审查。

## map 留出数据

在 `Ship-Unloader-Work/validation/r2g_map_holdout/input/` 的复制输入上，按 SHA 对齐旧 R2G 与 B2 输出后重放 B4；结果在 `Ship-Unloader-Work/validation/r2h_b4_map_holdout/`。08-02 的 R2G 三框因 B2 没有已确认 Vessel 而全部 `UNRESOLVED_VESSEL_ASSOCIATION`；4-22 无 R2G axes；5-21 和 8-17 的 R2G 零框不能由本轮精修恢复；5-29 的两框与 7-2 的一框仅为 `PARTIAL_HATCH`。5-29 的右上小框目视疑似上层结构，**不得把它计为已标定船舱**。7-15 缺同 SHA 的 B2 输出，故不伪造结果。

这说明下一阶段仍需在多船与无 Height 候选处解决 proposal 召回和结构角色；B4 的矩形精修不能代替该阶段。当前静态结果也不具备双雷达多帧精度声明的条件。
