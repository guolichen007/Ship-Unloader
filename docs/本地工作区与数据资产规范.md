# 本地工作区与数据资产规范

## 1. 三目录分离原则

Git 仓库不再兼任源码目录、原始数据仓库、构建目录、验证输出目录。数据与产物放在仓库内两个 `.gitignore` 忽略的子文件夹，永不推送：

```text
Ship Unloader/                  # Git 仓库：代码 + 文档 + 去路径化契约
├── .git/ docs/ ship_perception/ third_party/
├── README.md / CLAUDE.md / AGENTS.md / .gitignore / .gitattributes
├── Ship-Unloader-Data/         # 永不推送：原始数据 / legacy / 标注 / 清单
│   ├── raw/map/                #   map.zip（全量地图资产）
│   ├── legacy/                 #   （hold_detector 因挂载层 rename 保护暂留原位）
│   ├── annotations/
│   └── manifests/
└── Ship-Unloader-Work/         # 永不推送：build / validation / logs / reports / tmp
    ├── build/
    ├── validation/
    ├── logs/
    ├── reports/
    └── tmp/
```

- `SHIP_UNLOADER_DATA_ROOT` → `Ship-Unloader-Data/`
- `SHIP_UNLOADER_WORK_ROOT` → `Ship-Unloader-Work/`
- `hold_detector/` 为只读 legacy 资产，当前因沙箱挂载层 rename 保护暂留仓库根（已 `.gitignore` 忽略）；Windows 本机可迁移到 `Ship-Unloader-Data/legacy/hold_detector/`。

## 2. Git 允许 / 禁止

- **允许 commit**：源码、文档、非敏感去路径化 dataset contract / alias / SHA 元数据。
- **禁止 commit**：原始 PCD/PLY、`map.zip`、客户原始路径、大图、模型私有资产、build 产物、validation 输出。

## 3. 数据资产

- `map.zip`（SHA-256 `24f0c5dc…682bff`）位于 `Ship-Unloader-Data/raw/map/`，是当前全量地图资产，不得进 Git、不得进 Git LFS。
- 13 个物理扫描（8 PCD + 5 PLY），去重索引见 `ship_perception/datasets/map_physical_scan_dedup.json`。
- `hold_detector/` 是只读 legacy 资产，产品代码不 include/link；`--data-root` 参数化指向其位置。

## 4. 已完成的目录治理

- `map.zip` → `Ship-Unloader-Data/raw/map/`
- `validation/` → `Ship-Unloader-Work/validation/`
- `build-*`（可再生成 cmake 产物）已删除
- `hold_detector/` 暂留原位（挂载层限制），Windows 本机可迁移

## 5. 环境变量约定

新脚本一律用 `--output-root` 或 `SHIP_UNLOADER_WORK_ROOT` / `SHIP_UNLOADER_DATA_ROOT` / `SHIP_UNLOADER_LEGACY_ROOT`，禁止硬编码本机绝对路径，禁止把大量日志/JSON 堆进 Git 根目录。
