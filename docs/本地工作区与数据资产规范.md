# 本地工作区与数据资产规范

## 1. 三目录分离原则

Git 仓库不再兼任源码目录、原始数据仓库、构建目录、验证输出目录。

```text
Desktop/
├── Ship Unloader/            # Git 仓库：代码 + 文档 + 去路径化契约
├── Ship-Unloader-Data/       # 永不 commit：原始数据 / legacy / 标注 / 清单
└── Ship-Unloader-Work/       # 永不 commit：build / validation / logs / reports / tmp
```

- `SHIP_UNLOADER_DATA_ROOT` → `Ship-Unloader-Data/`
- `SHIP_UNLOADER_WORK_ROOT` → `Ship-Unloader-Work/`

## 2. Git 允许 / 禁止

- **允许 commit**：源码、文档、非敏感去路径化 dataset contract / alias / SHA 元数据。
- **禁止 commit**：原始 PCD/PLY、`map.zip`、客户原始路径、大图、模型私有资产、build 产物、validation 输出。

## 3. 数据资产

- `map.zip`（SHA-256 `24f0c5dc…682bff`）位于 `Ship-Unloader-Data/raw/map/`，是当前全量地图资产，不得进 Git、不得进 Git LFS。
- 13 个物理扫描（8 PCD + 5 PLY），去重索引见 `ship_perception/datasets/map_physical_scan_dedup.json`。
- `hold_detector/` 是只读 legacy 资产；未完成引用参数化前不迁移。

## 4. 迁移

本机迁移脚本：`.local/migrate_workspace.sh`（Windows Git Bash 执行）。hold_detector 本轮不移动。

## 5. 环境变量约定

新脚本一律用 `--output-root` 或 `SHIP_UNLOADER_WORK_ROOT` / `SHIP_UNLOADER_DATA_ROOT` / `SHIP_UNLOADER_LEGACY_ROOT`，禁止硬编码本机绝对路径，禁止把大量日志/JSON 堆进 Git 根目录。
