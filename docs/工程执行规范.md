# 工程执行规范

所有 Claude / Codex / ClaudeCLI 任务的统一约束。优先级高于任何单个任务指令。

## 1. 任务开始必回执

```
BRANCH=
BASE_SHA=
HEAD_SHA=
git status
```

并明确本轮 `IN_SCOPE`、`OUT_OF_SCOPE`、`STOP CONDITION`。

## 2. 开始前必读

- `CLAUDE.md` / `AGENTS.md`
- 当前 Architecture Freeze 文档
- 对应阶段验收契约

## 3. 禁止自行修改（须明确授权）

- 架构
- 数据 split
- 门禁 / 阈值
- holdout 状态
- V1.4 冻结源码（72 文件，`verify_v14_frozen.py` 校验）

## 4. 数据与产物位置

- 原始数据：repo 外 `SHIP_UNLOADER_DATA_ROOT`，不 commit。
- build / log / validation / tmp：repo 外 `SHIP_UNLOADER_WORK_ROOT`，不 commit。
- Git 只放代码、文档、去路径化契约与 SHA 元数据。

## 5. 提交规范

- 一项逻辑一个 commit；禁止一次 commit 混目录清理 + 架构修改 + 产品算法修改。
- 提交信息、README、验证报告：中文企业级文案。
- 技术标识、类名、配置字段：英文。

## 6. 失败处理

- 任何失败必须保留失败证据，说明根因是否闭环。
- 禁止为了 PASS 降低标准或改写门槛。

## 7. 红线（未授权禁止）

- merge main、tag、force push
- 访问 sealed holdout 做算法评分
- 把旧 weak holdout 包装成最终商业盲测

## 8. 任务结束必回执

```
PREV_SHA=
NEW_SHA=
CHANGED_FILES=
COMMANDS=
TEST_RESULT=
REGRESSION_RESULT=
WORKTREE_CLEAN=
PUSH_STATUS=
NEXT_BLOCKER=
```
