# V1.4 船体稳定跟踪核心版实现说明

## 版本边界

本分支从 `06af2d66262afd828edf2eef72b6ce1bc6969797` 开始，六个逻辑提交依次完成依赖、接口、真实后端、Track-and-Map、测试与中文文档。修订后的用户计划优先于归档的原始实施文档。原 M0 配置与断言保留；原始 M0 正式通过报告仍需真实证据归档，不生成替代报告或标签。

本版验证配准和闭环参考地图；正式精度使用瞬时帧，80 ms 船体运动扫描只作诊断。不包含 ES-EKF、最终可观性/协方差标定、TEASER++、完整 LOST/重定位、Polygon、控制地图、AI 或 PLC 控制。现场保持 `SITE_PENDING`。

## 依赖与接口

small_gicp 固定 `v1.0.0` / `fd29d8cf94cf05ed7ad21c81c27b65963110adb5`。源码快照、许可证和逐文件 SHA-256 清单位于 `third_party/small_gicp/`，未修改原始源码。自有 CMake wrapper 实例化 `Registration<GICPFactor, SerialReduction>`，关闭 OpenMP、PCL wrapper、TBB、march-native 和自动下载，链接已解析的系统 Eigen。这样也避免了上游 helper 的 OpenMP 预处理指令在 MSVC 上不兼容的问题。

`RegistrationBackend` 接收局部 float 点云、`shared_ptr<const TargetSnapshot>`、double 初值和方法，返回 `T_target_source`、可用性标志、原始 H、原始目标函数、收敛/有效状态、失败原因、对应点数、迭代次数、共同质量和耗时。接口不含第三方类型。

GICP 使用 KD-tree；VGICP 只为当前不可变快照构建 Gaussian target，不把上游增量体素容器用作长期地图。PCL GICP 是独立适配器，PCL1.10 的内部变换为 float，适配器显式转为 double 后接受相同健康检查；不静默正交化。PCL 的 H/原始目标函数不可用，字段标志为 false。

统一质量在原始局部 source 与同一目标快照上计算：阈值距离内源点比例为 overlap，欧氏最近邻距离平方均值为 fitness，其平方根为 RMSE。H 是上游线性化结果，排列 `[旋转, 平移]`，右扰动 `T ← T exp(δξ)`；它不是已标定协方差。PCL 不承担完整矩阵的版本精度放行，但 PCL-ON 的已知 SE(3) 基础门禁必须实际执行、收敛、有效，且平移误差≤5 cm、旋转误差≤0.5°，否则验证失败，不能只凭成功链接或调用放行。

## 数学与传感器边界

TRACKER 的公开类型只包含传感器点、报告时间、配置外参、吊机位姿与初始化先验。`TimedPoint.time_offset_ns`、`T_C_L1/T_C_L2`、`T_W_C(t)` 正常进入补偿过程。GT_SCORER 的船体轨迹、注入时间/外参错误、身份索引和静态标签位于测试模块，跟踪器不依赖其头文件。

初值、返回矩阵、吊机位姿与外参均检查有限值、齐次末行、旋转行列式和正交性。行列式与正交性默认容差 `1e-6`；可用 H、原始目标函数和质量指标必须有限。非法结果不更新有效 pose、候选或地图，保留失败原因和数学失败标志。返回的数值字段置为安全值并标记不可用，不把非法矩阵伪装成有效测量。

## 固定坐标系与闭环

首帧使用配置的方向先验、运行时先验与点云质心建立 provisional Ship Frame B；之后不自动改轴。所有世界变换为 double，只有局部存储转 float。每帧按每点报告时间补偿吊机运动并统一双雷达到 C，再执行：

```text
T_B_C_initial = inverse(T_W_B_previous) * T_W_C_current
source(C) → target(B) 配准得到 T_B_C
T_W_B_current = T_W_C_current * inverse(T_B_C)
```

Tracker 独立复核后端 valid、健康、共同质量和运动跳变。失败时报告无效观测，保存上一有效世界位姿供下一次预测；无效帧不生成虚构评分距离。

## 参考地图防污染

帧开始获得快照 revision N，整个配准与共同质量计算只读该对象。本帧完成配准和检查后，才提交候选、晋升和隔离。旧快照的点和 revision 永远不修改，后续帧才可能使用 N+1。

- `tracking_target_revision` 是本帧实际读取的目标；等于上一帧结束的地图 revision。
- `tracking_map_revision` 只在目标点集合改变时增加。
- `candidate_revision` 在接受的高质量地图事务后增加，用于追踪候选和支持证据处理。
- 被拒绝帧不提交地图事务，不产生新 revision，也不改变地图状态。目标字段记录实际快照，不能为迎合上一条日志的数值而隐瞒目标切换。

初始化对每个体素的全部输入点以 double 累加求质心；容量不足时按有序体素 key 选择保留集合。点的输入或 shuffle 顺序不决定代表点和容量截断结果，回归测试同时检查质心、点顺序与容量边界。

初始点是 `BOOTSTRAP_ANCHOR`。正常 promotion 不替换活动锚点；稳定多帧支持确认后标记稳定。**所有活动参考点，包括已稳定的 bootstrap 点和候选晋升点，始终接受明确自由空间冲突检查**；stable 仅表示历史支持，不赋予永久存活权。它们均可经过 `ACTIVE → SUSPECT → QUARANTINED`，支持恢复清除嫌疑，隔离后从后续 registration snapshot 移除，必须重新通过完整候选审核才可启用。恢复后的点仍可再次隔离。

冲突必须来自正常传感器射线：返回点明确在锚点之后、射线接近锚点且满足距离裕量。未观测、被遮挡或 FOV 外没有冲突票。移除后支撑不足会报告 `needs_reinitialization` 并停止接受后续新位姿；本版不自动重定位。

候选按体素聚合，同一帧最多贡献一次支持；连续不同帧支持、位置离散、RMSE 和 overlap 达标才能晋升。活动点位置固定，候选使用均值和增量方差，容量及 ROI 有界。默认值为支持 5 帧、离散 3 cm、TTL 10 帧、冲突窗口 20 帧、嫌疑 5 票、隔离 10 票，全部纳入 `v14.json` 哈希，属于 `V1.4_DEFAULT`，允许后续 SITE 调参。

## Synthetic 与评分

旧 M0 夹具和默认随机序列保持不变。V1.4 复用生成器，使用含甲板、围壁和非对称结构的稠密局部夹具，船体处于大世界坐标原点。按场景、种子、帧、传感器和用途派生独立随机流，分离噪声、dropout、时钟扰动、动态点和 shuffle。

独立视角场景改变 FOV；评分侧以“传感器 ID + 静态来源身份”计算相邻帧 Jaccard 变化率，逐帧要求 20%～40%。这些身份不会传给 tracker。

每个后端第一次初始化时固定 `T_S_B`，冻结 `S_reference = inverse(T_S_B) * S_static`。之后不作逐帧或全轨迹重新拟合。对隐藏标签为静态的观测计算 `NN(T_B_C_estimated * p_C, S_reference)`，排除注入动态点和离群点，保留正常测量噪声。输出各帧和整体 P50/P95/MAX、样本数，整体及每个有效帧 P95 都须不超过 10 cm。

闭环与 benchmark 分表。benchmark 使用同一对相邻冻结观测、同一吊机运动初值，并记录输入指纹；两个后端不使用各自的更优初值。闭环各有独立 pose、候选和地图。PCL-ON 时另对每个场景/种子的首对帧执行 PCL 对照；验收器要求这些 pose/quality 记录齐全、backend_executed=true、mathematical_failure=false，数学非法结果即使被适配器拒绝也使该通道失败。Full 不要求 PCL 在全部场景达到 GICP/VGICP 的精度水平。

## 放行条件与诊断

Quick 为 50 帧、seed42、五个核心场景；Full 为 200 帧、42/1337/2026、全部 11 个必测场景和 6 个诊断场景。两后端均须实际完成矩阵、通过已知 SE(3) 基础能力与关键安全断言，不能全部返回 invalid。

同一个后端须在所有必测场景、种子及配准/闭环通道达到：平移 P95≤5 cm、旋转 P95≤0.5°、有效率≥99%、不连续失败两帧、末帧有效且满足相同误差界限；闭环还须通过静态结构稳定性。不得逐场景拼接后端。另一后端的精度差距不阻塞，但崩溃、非法结果接受、缺证据和地图污染阻塞。

平甲板、时间损坏、大外参扰动、LOST、重复舱口和 80 ms 扫描仅诊断。捕获范围在冻结观测目标下扰动初值，覆盖 yaw ±1°/±3°/±5°、XYZ 各轴 ±0.2/±0.5/±1 m 及组合，不要求所有档位成功。首帧 provisional 先验变化另记 `GAUGE_ONLY_NOT_ABSOLUTE_RECOVERY`。

算法开发期间曾在 50 次迭代、`1e-4` 终止阈值下发现孤立 NOT_CONVERGED，现默认最多 100 次、平移/旋转终止阈值 `5e-4 m/rad`。以上版本验收门槛未降低。生产后端仅给比较与建议，不自动冻结。

研发优先级记录为 `PRIMARY_CANDIDATE=GICP`、`SECONDARY_CANDIDATE=VGICP`。依据修复前精确 SHA 的诊断证据，GICP 在退化平甲板上更稳定；保留 VGICP，最终生产后端仍由真实船数据决定。集中修复后重新执行完整矩阵，数值以新 SHA 的报告为准。

## 证据与限制

四类主 CSV 以场景/种子/帧/后端/通道关联；统一报告记录编译 SHA、配置哈希、数据 ID、系统与实际依赖，SHA-256 清单绑定所有产物。`series.csv` 是逐序列摘要。点云分别输出参考地图和每十帧抽取的累积观测，后者明确含动态点。

本机 PCL-OFF 的通过结果不代表 PCL 已编译或通过，也不代表 Ubuntu20 正式通过。最终 Windows 全新构建、Quick/Full 的实际结论以交付的精确 SHA 验证目录为准。后续按[统一交接](V1.4版本_Ubuntu20验证交接说明.md)先审查再正式验证。
