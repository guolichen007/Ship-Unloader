## 决定与范围

同一扫描可包含 0..N 个待核 VesselHypothesis；控制侧只接收一个有可追溯外部依据确认的 TARGET_VESSEL。连通域只能产生 SceneSupportCandidate，不能直接成为 Vessel 语义。空间分组、方向族和矩形证据须联合考虑：断裂船体可合并，噪声桥接可拆分，相同 yaw 的平行船仍可分开，码头不能因面积大而被选成目标船。目标船选择不由最大面积、最近距离或 Y 最小值自动决定。本轮仅建立受控目标契约与只读法证，不改变正式 detection、acceptance gate 或 V1.4 frozen 源码。

R2H-B 目标数据流：

```text
Raw XYZ
  → SceneSupportCandidate[]
  → coarse spatial support + AxisFamily + rectilinear evidence
  → VesselHypothesis[0..N] + local axis refinement
  → per-vessel {HEIGHT_BASIN, BEV_RECTILINEAR, RAW3D_STRUCTURAL} Proposal Pool
  → HATCH_PROPOSAL / PARTIAL_HATCH / PROVISIONAL_HATCH / UNRESOLVED
  → R2F fusion → R2G inner-edge refinement (仅对证据足够的矩形)
  → 外部 Target Selection → TARGET_VESSEL_CONFIRMED → CurrentShipModel
```

Height、BEV、Raw3D 均只能提供可追溯 proposal/evidence。RawXYZ 跃迁、货物坡脚、码头线、船体外轮廓和驾驶室不得改名为 Hatch steel boundary。允许的场景支持状态为 `SCENE_SUPPORT / VESSEL_CANDIDATE / VESSEL_HYPOTHESIS / BACKGROUND_STRUCTURE / UNRESOLVED`；`TARGET_VESSEL_CONFIRMED` 是外部选择后的不同状态。单帧 Hatch 状态为 `HATCH_PROPOSAL / PARTIAL_HATCH / PROVISIONAL_HATCH / UNRESOLVED`。两边只可 proposal 或 unresolved；三条独立强边且第四边弱、另有 opening/rectilinear 证据时可 partial；四边实测支持才可 provisional。几何约束不能生成不存在的钢边。横梁、船体外侧和上层建筑需要独立角色，窄框不能仅凭宽度拒绝或确认。

## 冻结契约冲突与受控修订

原 `README.md` 和 `docs/00` 将“当前作业目标船可见 1～3 Hatch”写成主链目标，后者仍给出 `Target Vessel Seed/ROI → H=1/H=2/H=3 Joint Hypothesis`。`docs/01` 也以 H=1/2/3 比较为技术路线。数据契约 `docs/V1.5-R数据契约_V2场景语义.md` 已是 `scan → vessels[] → hatches[] → edges[]`，并登记 5-29 为三船、7-2 为双船开发压力样本。二者描述不同层次却未划清边界，造成把开发样本数量误读为 Discovery 硬上限的风险。

本评审把 1～3 舱明确限于当前 Development acceptance coverage；新的 Scene/Hatch Discovery 容器必须能表示 0..N，不预设具体船型的舱数、长度或宽度。同一艘实船的舱宽相近可作当前 Vessel 内弱一致性诊断或最后的证据平分；不得跨 Vessel 使用，也不得凭先验补边。`R2F.solve` 实际可输出多个矩形，没有 `max_hatches=3` 硬编码；R0 measurement 的 `top_k=5/50/55` 是 proposal NMS 工作量上限，不等价于 R2F 的舱数上限，但后续必须审计它们是否在多船路径上造成漏召回。旧文档 H=1/2/3 与当前研究函数的不同状态均保留为历史事实。

本次在 `docs/00` 和 README 加了 R2H 附注，原冻结管线正文保留为现有行为记录。R2H-B 才能替换正式管线，且必须经过本 ADR 中的反证和真实场景 gate；不得把 ADR 的目标图宣称已经上线。

## 六个待验证根因及代码事实

1. **SINGLE_LARGEST_SUPPORT_BIAS**：`heightmap_topology._vessel_support` 对闭合后的有效栅格做连通域，返回 `labels == argmax(sizes)`；其他 component 在 Height 前丢失。component 是否为船仍须图像/独立标注核对，不能由该统计直接断言。
2. **GLOBAL_STRONGEST_REGION_SUPPRESSION**：`detect_regions` 以整景 `strongest * minimum_relative_region_score` 过滤 `_choose` 结果。即使多个 support 存活，弱船区域仍可能被压掉。
3. **SINGLE_GLOBAL_AXIS_BIAS**：`rectangle_fusion.solve` 对全部未禁用结构边运行一次 `structural_axes`，并用这一组轴构建整景 BEV；多船不同 yaw 时存在方向串扰风险。Raw angle bin 只作诊断，不是 VesselHypothesis。
4. **HEIGHT_ONLY_PROPOSAL_ENTRY**：`solve` 在 `for node in height_regions` 内枚举矩形，Height=0 时无候选尝试；轴若先无法解出会更早返回。
5. **PROPOSAL_CALIBRATION_GATE_COUPLING**：`_candidate_rectangle` 虽在前段容许三条 observed、最多一条 geometry constrained，后段要求 `strong=4` 且 `dual_return=4`、`majority_supported>=3`。这会把可追踪的三边 partial 一起丢掉，不能简单降低确认门槛；应分流为 PARTIAL。
6. **FIXED_HATCH_CARDINALITY_ASSUMPTION**：文档冻结的 H=1/2/3 是契约冲突；R2F 实现没有该硬上限。R0 `top_k` 为候选预算，需在新的多船链中复核，不机械删除数字。

## R2H-A 只读法证与解释规则

`python -m ship_perception.r1_static.r2h_scene_forensics --scene-set normal6`，或 `--scene-set map-validation --validation-input-dir Ship-Unloader-Work/validation/r2g_map_holdout/input`。脚本从校验 SHA 的 Development 原始 PCD 或无标签 map 副本解码原始 XYZ，运行现有 Height → S4R1 → R2F → R2G；可选 trace 只写审计字典，不参与排序或接受。逐 scene 的 `stage_accounting.json` 与 batch summary 写入被 Git 忽略的 `Ship-Unloader-Work/review/r2h_a_forensics/`，不提交原始点、候选大表、图片或日志。审计包含点数、闭合栅格 component 的点/格数/面积/包围框、largest 选择与删除、Height 前后节点及 global score 删除、全局轴与离散度、角度族、矩形尝试数及逐候选的拒绝原因和边数指标。

这里的角度族仅对**现有 S4R1 产生的 Raw3D 结构边**分箱；它不是从所有 Raw XYZ 独立恢复的轴。4-22 在 Height=0 时 S4R1 边与角度族同时为 0，不能据此推断原始点云没有长直边。R2H-B 的 BEV/Raw3D 独立 provider 正是为打破这个入口循环而提出。

`first_bad_stage` 是**机械流水线定位**，不是人工真实 opening 真值。若 Height=0 且轴也无解，首阶段写 `HEIGHT_PROPOSAL`，`secondary_stage=AXIS_RESOLUTION`；有 rectangle 但某船仍遗漏，机械字段写 `NONE`，并在本 ADR 的人工逐船审查中指出缺口，不得把现有候选数等同船数。仅凭点云 component 数不能声称 vessel count。`stage_accounting.json` 无独立内沿 Golden，也不提供厘米级精度验收。

## 静态与未来多帧边界

当前 PCD/PLY 只有静态 XYZ，可验证单帧 scene separation 风险、proposal recall 与几何；不能声称已验证双 LiDAR 互补、时间关联、运动补偿、多帧补边或收敛时间。R2H-B 观测 schema 应预留 `observation_id/scene_support_id/vessel_hypothesis_id/hatch_hypothesis_id/frame_id/sensor_id/coordinate_frame/evidence_type/uncertainty/source_geometry`，当前 `frame_id=STATIC_SINGLE_FRAME`、`sensor_id=UNKNOWN`。未来数据具备 timestamp/sensor_id 后，顺序必须是 LiDAR → extrinsic → V1.4 motion compensation → track quality gate → Ship Frame → evidence accumulation；`TRACK_REJECTED` 不得进入 CurrentShipModel。

## Gate 与后续决策

- `GATE_SCENE_RECALL`：合理船体 support 不因 largest/global strongest 无记录消失；Wharf 不冒充 Vessel。
- `GATE_HATCH_RECALL`：人眼明显开口至少留 `HATCH_PROPOSAL/PARTIAL_HATCH` 及来源；仍须人工或独立证据审查。
- `GATE_PRECISION_REGRESSION`：Normal6 R2F/R2G 的旧 2/1/1/1/1/3 不得无解释退化，边界不得跳向 cargo/wharf/outer hull。

R2H-A 合成反证保留失败为 `expectedFailure`，代表已知欠缺而不是 gate 通过；双边歧义和只有横梁的场景必须保持未确认。B 阶段逐项消除预期失败，不能把 3 边 proposal 直接冒充 provisional。`STATIC_CALIBRATION=UNVERIFIED_NO_INDEPENDENT_INNER_EDGE_GOLDEN`，即使技术管线和召回门通过仍不宣布精准内沿验收。R2H-A 提交后停止，B 的实现须以本次 stage accounting 和独立审图为依据。

合成审计结果：`test_r2h_a_counterexamples.py` 共 14 项，3 项守恒/保守行为通过，11 项为**预期失败**。其中一条三强边加局部短弱边在 `FINAL_FOUR_SIDE_ACCEPTANCE_GATE` 被拒，trace 明确为 `strong_side_count=3`；一条 2 m 宽的实测升高横梁条带仍产生 `REVIEW_REQUIRED_RECTANGLE`，说明不能用“已有四条线”代替 opening 角色判别。两船同轴、不同 yaw、三船不等密度、码头更大、断裂同船、噪点桥接、Height miss、跨船轴/宽度泄漏均有可重现的红测试；红测试尚未转绿，三个 Gate 都**未达到 R2H-B 验收状态**。

本轮验证：R1 Python 99/99；R2H-A synthetic 14 项执行成功（11 项预期失败）；`ctest -C Release -LE quick_acceptance` 在新增测试注册前 34/34，新增 `v15r1_r2h_a_counterexamples` 定向 1/1；V1.4 frozen SHA 核对 72 文件通过。`v15_quick` 的 synthetic PASS、real_smoke FAIL、integration FAIL，与 R2G 记录的既有 gate 状态一致，不降门槛、不记为通过。R2H-A 的静态场景与 proposal gate 明确 `NOT_PASSED`；Normal6 旧矩形计数稳定仅表示计数回归，不是新的边界精度 Golden。
