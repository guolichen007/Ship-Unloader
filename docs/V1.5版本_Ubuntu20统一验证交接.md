# V1.5 Ubuntu20 统一验证交接准备

**当前不是正式交接。** 已推送的 `d10ab0e` 是阶段代码检查点，不是 IMPLEMENTATION_SHA；真实 Development 与 Quick 门禁仍未通过。以下命令用于后续同一精确 SHA 的独立验证准备，不能把开发矩阵当成最终放行报告。

## 固定环境与构建

目标 Ubuntu20、GCC9、CMake3.16、Eigen3.3.7、PCL1.10。必须使用系统 `/usr/bin/cmake`，记录实际依赖配置与头文件路径；不能用 PATH 中 pip CMake 或 `/usr/local` Eigen 的版本号代替真正被编译器使用的版本。

待 Codex 提供正式 SHA 后，在独立验证目录执行：

```bash
git fetch origin feature/v1-5-hold-structure-recognition
# IMPLEMENTATION_SHA 必须替换为本次交接中公布的 40 位 SHA。
git checkout --detach "$IMPLEMENTATION_SHA"
test "$(git rev-parse HEAD)" = "$IMPLEMENTATION_SHA"
test -z "$(git status --porcelain)"

EIGEN_CONFIG=
for candidate in /usr/lib/cmake/eigen3 /usr/share/eigen3/cmake; do
  if test -f "$candidate/Eigen3Config.cmake"; then
    EIGEN_CONFIG="$candidate"
    break
  fi
done
test -n "$EIGEN_CONFIG"
test -d "$DATA_ROOT"  # 外部只读 hold_detector 副本；验证前由执行者设置绝对路径

# 使用此前不存在的目录；不复用历史 build。
BUILD_DIR="build-v15-${IMPLEMENTATION_SHA}-$(date -u +%Y%m%dT%H%M%SZ)"
test ! -e "$BUILD_DIR"
/usr/bin/cmake -S ship_perception -B "$BUILD_DIR" \
  -DCMAKE_BUILD_TYPE=Release -DM0_WITH_PCL=ON \
  -DEigen3_DIR="$EIGEN_CONFIG" -DPython3_EXECUTABLE=/usr/bin/python3 \
  -DV15_DATA_ROOT="$DATA_ROOT"
/usr/bin/cmake --build "$BUILD_DIR" --parallel 2
cat "$BUILD_DIR/build_dependencies.txt"
/usr/bin/cmake -E chdir "$BUILD_DIR" /usr/bin/ctest --output-on-failure
```

检查 `build_dependencies.txt` 中实际 Eigen 为 3.3.7，路径指向系统目录；PCL 为 1.10。不满足目标环境时先报告 ENV_FAIL，不修改冻结产品源代码。

## 分项证据命令

外部资产路径通过 `DATA_ROOT` 指向 `hold_detector` 的只读副本；输出用独立 `VALIDATION_DIR`。运行器依赖 Python3 与 numpy，不联网下载源码或依赖。

```bash
python3 ship_perception/tools/verify_v14_frozen.py
python3 ship_perception/tools/audit_v15_decoder.py \
  --data-root "$DATA_ROOT" --output "$VALIDATION_DIR/decoder" \
  --pcl-executable "$BUILD_DIR/v15_recognize" --require-pcl
python3 ship_perception/tools/run_v14.py \
  "$BUILD_DIR/v14_evaluate" full "$VALIDATION_DIR/v14-full"
python3 ship_perception/tools/run_v15_synthetic.py \
  "$BUILD_DIR/v15_recognize" full "$VALIDATION_DIR/structure"
python3 ship_perception/tools/run_v15_development.py \
  "$BUILD_DIR/v15_recognize" --data-root "$DATA_ROOT" \
  --output "$VALIDATION_DIR/development"
python3 ship_perception/tools/run_v15_integration.py \
  "$BUILD_DIR/v15_integration" full "$VALIDATION_DIR/integration"
python3 ship_perception/tools/run_v15_isolation.py \
  "$BUILD_DIR/v15_recognize" --output "$VALIDATION_DIR/isolation"
```

分项通过后，先运行 `audit_v15_delivery.py` 检查覆盖及身份，再运行 `freeze_v15_evaluation.py` 签署封存集使用记录。只有冻结工具确认 Development、Synthetic、集成等前置条件均合格，才能调用 `run_v15_development.py --include-sealed-holdout --freeze-record ...` 对四份封存集统一评分。本阶段的 Development 与 Quick 为 FAIL，因此没有签署冻结记录，也没有做封存集算法评分。正式通道禁止使用 `--rescore-existing` 代替真实执行。
