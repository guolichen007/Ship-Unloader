# ROS2 现场一键识别运行说明

适用：Ubuntu 22.04、ROS2 Humble、Python 3.10。入口只做一次点云复核，不启动建图，不接 PLC。脚本、命令、日志和图示使用英文。

## 首次准备

先安装 ROS2 Humble 并确认 `source /opt/ros/humble/setup.bash` 可用。进入当前分支仓库：

```bash
git clone --branch codex/ros2-hatch-hardening-v1 git@github.com:guolichen007/Ship-Unloader.git
cd Ship-Unloader
source /opt/ros/humble/setup.bash
sudo apt-get install python3-venv python3-pip libeigen3-dev \
  python3-colcon-common-extensions ros-humble-ament-cmake-python \
  ros-humble-ament-cmake-pytest fonts-noto-cjk
python3 -m venv --system-site-packages .local/ros2-venv
source .local/ros2-venv/bin/activate
python3 -m pip install -r requirements-ros.txt
export PYTHONNOUSERSITE=1
python3 -s -c 'import rclpy, numpy, scipy, matplotlib; from jsonschema import Draft202012Validator'
```

使用独立 venv 保留 apt 提供的 ROS2 包，并固定数值依赖；不要向系统 Python 混装另一套 NumPy。脚本默认禁用用户 site-packages，避免系统 SciPy/Matplotlib 与用户安装的 NumPy 混用；venv 的包仍可读取。可用 `PYTHON_BIN=/absolute/path/to/python3` 指定解释器。

PCD 脚本只需数值依赖与 jsonschema，不 import rclpy；已准备依赖时可在没有 ROS 的 Linux/Python 环境离线运行。

## PCD 一次识别

```bash
./scripts/run_ship_hatch_pcd.sh --pcd /data/map.pcd --save-snapshot
```

支持 binary PCD 的字段重排、FLOAT32/FLOAT64 XYZ、整数或浮点 intensity、显式 padding 字段；scalar ASCII 布局可读。`binary_compressed` 明确拒绝，不把未知编码当成成功。XYZ 非有限行删除时 intensity 同行删除；原文件不修改。历史 PCL 尾部 padding 只沿用已有文件 SHA 授权，不放宽到任意文件。

```bash
./scripts/run_ship_hatch_pcd.sh --pcd /data/map.pcd \
  --frame-id map --output-dir ./output --save-snapshot
```

## 从最终地图 topic 一次识别

先让建图发布器完成地图，并使其以 ROS2 `sensor_msgs/msg/PointCloud2` 发布 `/ship_scan/map`。随后：

```bash
source /opt/ros/humble/setup.bash
source .local/ros2-venv/bin/activate
./scripts/run_ship_hatch_once.sh --save-snapshot
```

只读取一条完整消息，不拼接两帧；收到后销毁订阅，再执行算法。字段 offset、重排、point_step、row_step、organized 行 padding、大小端、FLOAT32/FLOAT64、整数 intensity 均由独立 codec 校验。先检查点数和布局，再创建大数组；默认最多 1200 万源点，范围限制来自现有配置。

| 参数 | 默认 | 作用 |
| --- | --- | --- |
| `--topic` | `/ship_scan/map` | ROS2 地图话题 |
| `--qos` | `auto` | `auto / map / sensor / reliable` |
| `--timeout-sec` | `30` | 包含发现与采集的总等待上限 |
| `--output-dir` | `output` | 每次建立独立结果目录 |
| `--save-snapshot` | 关闭 | 保存同帧 NPZ，便于离线复核 |
| `--no-legacy-evidence` | 关闭 | 禁用旧几何比较，检查独立逐船链 |

`--save_snapshot`、`--output_dir`、`--timeout_sec` 作为已有参数别名保留。

### QoS 行为

AUTO 先查询发布者类型、数量与 offered QoS，再选择兼容的 reliability 和 durability。未知 QoS 或多个发布者保持明确错误，不随机选择。最终 offered/selected QoS、ROS_DISTRO、RMW、Domain ID、frame_id、时间戳、采集耗时均进入结果或失败诊断。

| 发布者 | AUTO 选择 | 现场含义 |
| --- | --- | --- |
| Reliable + TransientLocal | Reliable + TransientLocal | 可在发布之后加入，接收保留地图 |
| Reliable + Volatile | Reliable + Volatile | 等待下一次真实发布 |
| BestEffort + Volatile | BestEffort + Volatile | 兼容传感器式发布，等待下一次发布 |

Volatile 日志为 `MAP_IS_VOLATILE: late subscriber cannot rely on historical delivery; waiting for next publish`。脚本不会要求设备提供它没有保留的历史消息。`--qos map` 强制 Reliable + TransientLocal，`sensor` 为 BestEffort + Volatile，`reliable` 为 Reliable + Volatile；不兼容时明确拒绝。

现场跨主机通信需保持 ROS_DOMAIN_ID、网络与 RMW 可互通。ROS1 话题不会因名称相同而自动成为 ROS2 话题；需要设备侧 ROS2 输出或另行配置桥接。本仓库生产脚本不依赖 ROS1。

## 可选 colcon 安装

只运行仓库脚本无需编译 C++；需要标准 `ros2 run` 或 launch 时，在激活上述 venv 后执行：

```bash
colcon --log-base Ship-Unloader-Work/ros2/log build \
  --base-paths ship_perception \
  --build-base Ship-Unloader-Work/ros2/build --install-base install \
  --symlink-install --cmake-force-configure --packages-select ship_perception \
  --cmake-args -DCMAKE_BUILD_TYPE=Release -DM0_WITH_PCL=OFF \
  "-DPython3_EXECUTABLE=$(command -v python3)"
source install/setup.bash
ros2 run ship_perception ship_hatch_once --save-snapshot
ros2 run ship_perception ship_hatch_pcd --pcd /data/map.pcd
ros2 launch ship_perception hatch_once.launch.py topic:=/ship_scan/map output_dir:=output
```

`--base-paths ship_perception` 避免扫描 Work 中的旧复现仓库。PCL-OFF 是 Python 工具和 C++ 开发验证配置，不能当作 V1.4 正式 PCL 验证。保留 standalone CMake；正式 C++ 复验按 [工程入口](../ship_perception/README.md)安装 PCL 并执行独立门禁。

复用构建目录且 Git HEAD 已变化时，`--cmake-force-configure` 刷新二进制内嵌 SHA。仅执行增量编译可能仍保留旧身份，G5 会明确失败；不能通过修改门禁或忽略失败解决。

## 结果和异常

五份正式文件、可选快照及标注含义见 [README](../README.md)。`03_results.json` 使用 `ship_perception.hatch_once.2`：输入身份、冻结归属、局部召回/拒绝、逐边 section、四相位、角点、不确定性、阶段耗时、首次失败阶段都可审计。

两个现场入口均自动生成 `05_hatch_corners.json`，终端打印 `HATCH_CORNERS_JSON` 路径。坐标为原始输入 frame 的米制 XY，顺序是四条最终直线的 `U0/V0`、`U1/V0`、`U1/V1`、`U0/V1` 交点，不是按图片像素或全局 X/Y 极值重排。未决组保留 `UNRESOLVED_OPENING_GROUP` 和未知真实舱数。已有新版完整结果也可单独导出，不必重复点云计算：

```bash
python3 -m ship_perception.perception.coordinates \
  --result output/RUN/03_results.json --output output/RUN/05_hatch_corners.json
```

终端的 `UNRESOLVED_PROPOSAL_COUNT` 表示仍需人工检查的未精修提案总数，可能包含同一对象的竞争解释，不能作为舱数。即使 `HATCH_REVIEW_COUNT=0`，仍应查看 JSON 中 `per_vessel_status[].unresolved_review_proposals` 的实测来源和 `reason`；货物接近甲板高度时，低盆地不足不能单独证明没有舱。提案的 `proposal_boundary_xy` 是搜索范围，不是最终钢内沿。

| 错误/状态 | 操作 |
| --- | --- |
| `NO_PUBLISHER` | 检查 ROS2 图、话题名、Domain 和发布器是否存活 |
| `WRONG_TOPIC_TYPE` | 将发布类型改为 PointCloud2 |
| `MULTIPLE_PUBLISHERS_AMBIGUOUS` | 停止重复发布或选用唯一地图话题 |
| `INCOMPATIBLE_QOS` | 使用 AUTO 或核对发布者 offered QoS |
| `CAPTURE_TIMEOUT` | Volatile 需要下一次发布；核对网络和超时 |
| `UNAVAILABLE_CONSTANT_DEVICE_SIGNAL` | 几何照常运行，当前强度没有可用对比 |
| `PARTIAL / UNRESOLVED` | 查看失败边和原始点支持，不能据此自动作业 |

Ctrl+C 返回 130 并清理节点/订阅；失败仅生成 `failure_*/failure.json`。局部几何歧义保留 diagnostics，继续其它船/舱；输入、配置或 schema 损坏才是整帧失败。退出 0 表示输出完整，不表示识别精度或全部船舱通过。
