# R3-N 跨平台密度首差与隔离修复

基线：`0695546e6655408aa10b545e4223a5409586ddbd`。本阶段仍为 NO-GO；真实三平台复验、刚体、污染反例和人工审核均须另行出具证据。历史失败不删除。

## 已测首差

同一输入的 1,076,315 个局部 Raw 点字节摘要一致；细栅格计数、中位高度、最小高度、最大高度、两个方向的高度转折和竖直跨度掩码均完全一致。600 个同参数 Raw 查询的结果也完全一致。

更早的差异发生于密度转折：Windows 与 Ubuntu22 的两个方向分别有 294、279 个格间接口判定不同，全部满足 `(较大计数+1) = 2*(较小计数+1)`。`log1p` 差与 `log(2)` 在此处相差一个浮点末位。BEV 片段数量因此为 1914 / 1918，同一开口 V1 围合证据选中不同片段带，保守范围先相差 1.10 米，之后才改变 Raw 测站及角点。因此不能归因为新法向缓存，也不能仅在求解器末端补偿。

## 最小修复与冻结边界

只在 V2 复核证据视图中，用整数比较 `high + 1 >= 2*(low + 1)` 实现原有闭区间密度比例门。保留双侧占据及最少回波条件，不增加容差、位置扰动、配置或阈值。计数先转 int64，避免原 int32 加乘溢出。

冻结的 R1/B2 函数及其适配器不改动。历史 B2 专家及既有 S4 拓扑继续接收原缓存；V2 的局部侧边比较视图复用该缓存的栅格与 Raw3D 支持，只重建 BEV 密度证据。新 BEV 来源使用独立的视图标识，不能冒充冻结拓扑中的同序号片段。由于冻结的片段函数没有通道注入接口，V2 内保留相同片段分组和证据导出循环；单测验证远离临界比例时与原函数逐字段一致，包括断续支撑、来源、覆盖和位置。

这属于正确性修复。真实输出若变化，必须列出逐边原因并重新提交受影响舱供人工审核；不得声称旧数值相等就是物理精度通过。钢边未认证，设备控制资格保持 false。

## 单变量历史与保护门

首次提交 c734ce2 在三平台的 10-26 完整 CLI 上保持相同两舱，最大差约 3.8e-14 米。但随后真实 11 景保护运行发现：将新 BEV 视图同时用于既有 S4 拓扑，会改变 08-01 两舱的拓扑身份和边界（最大约 1.20 米），没有独立物理证据支持该改动。该应用范围不获批准。后续将精确比例限定到已定位首差的局部侧边比较入口，保留冻结拓扑的输入合同；仍须重新执行三平台和 11 景保护验证，不能沿用首次提交的通过结论。

N1 两项工作树外的最小坐标反证分别隔离了测站/显示值和仅 Raw 测站。两项都减小合成平移误差，但都导致 4-22 的已有复核建议未采用，最大角点相对保护基线回退约 2.16 米。按任务书连续两项严重回退的停止条件，停止 N1 改造，两项均未装入产品。08-02 旋转合舱保持 FAIL。不能将合成平移收益单独表述为整链等变通过。

N3 原 water fixture 的构造为 `vessel(1, extra="water")`：确有一个带四壁的真舱口，旧负例标签不成立。其历史结果保留，补充只含背景水面及岸面、无船舱的独立负例。quay_water_pollution 的首差是两个 B1 船体提名且无可信泊位参考，选择阶段保持未决，未进入开口召回。不能据此篡改真实两舱数量，也不能把未指定泊位自动当作已知目标船。
