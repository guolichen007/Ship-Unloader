# 船舱识别算法实现说明

适用：V2.4 结构区域实验开发分支，2026-10-29。描述代码行为，不表示历史召回、钢内沿精度或现场放行已经通过。

## 区域与测量独立

`region_model.py` 定义 OpeningRegion、TopologySupport、BoundaryMeasurement 与 EvidenceSource。高度转折最多为 SUPPORTING，不充当强结构或实测钢边。区域提名不再要求三条强实测边；明确选船、非退化及独立拓扑提名仍是必要条件。精修结果与失败记录进入区域注册表，原保守边界及搜索范围保留；其他候选锚点上的移动保护不能授权裁剪本区域的原边。

`structural_family.py` 在冻结 B1 船局部坐标中按既有 corner_join 聚合 primary provider，保留 Raw 观测区间、rho 模式、间隙、可见性和原始索引。未知上下文和邻船不拥有 primary 线族。observable 支持比只在有支持或明确反证的区间中计算；占据格但没有结构测量仍为未决，不能自动判为边不存在。名义轴方向一致性不等同于 Raw 直线拟合精度。线族只扩展搜索、提供证据和关联，不能复制最终 rho 或靠相同线族强行合并身份。目前片段归属与完整区域编译仍未解决。

## 输入与靠岸船选择

PCD 和 ROS2 单帧共用 `PointCloudFrame`、`perception/cli.py` 与 `pipeline_v2.py`。ROS2 保持原有 QoS 与单消息采集；算法不依赖 rclpy。B1 每帧一次，船体轴、原始点索引与哈希、support ID 和分类冻结为 `SceneEvidenceContext`，各专家不重新分船。

`berth.py` 优先校验现场参考坐标系、码头直线、朝水方向和作业范围，按分段近岸距离/MAD、平行关系及工作区重叠选一艘船，不按点数、面积或雷达距离选船。自动参考需要可信观察位置，经 BEV 前轮廓、稳健直线、分布和宽陆侧支持检查；map 原点不自动等于雷达位置。无可靠参考的多船为 `MULTI_VESSEL_BERTH_AMBIGUOUS`，不进入专家；单船可作未认证的复核。

`SelectedVesselRawContext` 保存原始索引及近邻未知背景，排除已识别其他船。共同 support 只有唯一已分辨核心时才允许借用其未决侧带；不把其他船或无关建筑纳入精修。现场 YAML 不允许船尺寸、舱数或已知舱角坐标，模板默认关闭。

## 多专家与冻结范围

`CandidateProposal` 保存不可变证据、边界、船体和 lineage。联合无损保留全部提案；一个专家没找到候选不能删除其他专家的候选。

| 专家 | 提案依据 |
| --- | --- |
| LegacyProposalExpert | 原样调用历史 B2 `propose_for_vessel`，完整提案及证据哈希 |
| HeightBasinExpert | 全部局部实测高度族、低区域和 ring shoulder |
| StructuralLineExpert | 同船 Raw3D/BEV 线族及有符号 Raw 边模式 |
| LocalEnclosureExpert | 多边三维立面支持的结构包围 |
| LoadedHoldExpert | 高装载区域与结构闭合，不按货物高度硬拒绝 |
| LargeSandHoldExpert | 实测长大外围结构替代假设 |
| LayoutRecoveryExpert | 独立对象之间的测量搜索区 |
| MultiHoldLayoutExpert | 重复实测结构与 cross-deck 支持的拆分假设 |

`legacy_proposal_freeze.json` 校验历史原语和 v15 配置共 56 个文件，真实输入另比较完整 B2 proposal/evidence 哈希。Legacy 不运行独立最终精修。旧 R2F/R2G/B4/B5 仍在显式 `--pipeline v1-diagnostic`；旧完整链的召回尚未全部迁移，冻结 B2 输出不等于旧最终效果已全部保留。

## 物理查询与统一验证

V2.2 将 `OpeningRegionSeed` 放在新增结构闭合之前：选中船 → 既有 Height Basin/Legacy 搜索证据 → 嵌套高度层去重、横向低区合并与纵向关系诊断 → 区域附近的全部侧线提名 → 原 RawProbe 与共享最终精修器。区域和侧线提名都不是最终边，不新增 Expert。边界不完整的低区保留 secondary 诊断及原提案；低区连接多个纵向对象时保留 compound 关系，不能因此直接合舱。相邻地板低区只有在既有 Legacy 开口搜索共同支持时才合并搜索范围，这不证明舱数。

`BoundaryLineGraph.region_searches` 不枚举全局四线矩形笛卡尔积；每个区域保留四侧附近的所有候选线，交给原物理门解决。报告 U/V 线数、局部对边组合机会、实际矩形枚举数、区域过滤及去重数量。明显低区不足且存在实测高装载歧义时，保留选中船核心的未决结构工作区；它不是一个默认船舱。Legacy 冻结提案仍原样保留，区域方法没有固定舱数或 Top-K。

V2.1 的 `LegacyPostB2EvidenceAdapter` 只在选中船的既有数据与缓存上恢复 post-B2 角色、侧模式和分隔证据，不重跑第二套全局 `prepare_geometry` 或独立最终精修。名义邻接闭合与有独立结构支持的外围替代假设保留原始来源；内部横向面覆盖只调整调查顺序，不强制拆舱或固定舱数。编译按名义几何/拓扑/来源去重，失败代表不能删除未测成员。

`deck_ring` 在 V2 层按轴向位置索引筛选，随后仍调用冻结的原侧证据谓词，保留 provider 顺序、原覆盖、浮点边界及全部来源。粗面搜索优先级只用于排序，不能作为物理边准入依据。

`PhysicalBoundaryQuery` 按船体、四条物理边模式、隔板拓扑和相同站位聚合，保留全部来源。大框包含小框、面积大或重叠不能证明它们是同一物理舱；未知模式不伪装成相同钢边。

统一状态为 `PROPOSED / VALIDATED / PARTIAL / UNRESOLVED / REJECTED`。硬拒绝仅来自退化、原有物理尺寸限制、明确其他船/岸侧或强船外低连通。缺高度、满载、缺一边、布局异常和 B1 不完整不作硬拒绝；独立包围充分的装载歧义候选可继续 Raw 调查，仍不是已确认开口。

外部低连通只沿实测占据格传播，空白不作通路。V2 的 `UNKNOWN_CONTEXT` 和裁剪网格边界不作强 exterior seed；只有明确外部归属播种，并结合 containment、deck ring、coaming 和泊位关系。JSON 区分已知外连、未知上下文和包含状态，没有固定水面 Z。

## 布局只排序与搜索

`VesselLayoutModel` 测量局部 beam、port/starboard margin、占宽关系和对称性，没有固定 width ratio。至少两个具有独立 Raw 支持的对象才能建立 weighted median/MAD 的宽度、中心线及长度族；宽度影响强于长度，首尾舱和单舱不因尺寸不同被硬拒绝。

布局不改坐标。输出 `measured_width_m / layout_median_width_m / width_deviation_m / layout_prior_used / boundary_modified=false`；最终多边形不接受 median width 回写。缺物理边的搜索区为 `UNRESOLVED_LAYOUT_GAP`，不补框。

Cross-deck 要求实测横向 band、与邻侧 deck 的高度关系、平坦性及两个不同位置的合格三维立面。仅有货堆脊不拆分；通过时也只复用已经观测的子结构边，生成 `SPLIT_HYPOTHESIS`。不能凭布局给两个舱强设一条共同 U 线。

## 共享 Raw 精修

`RawBoundaryProbe` 只做候选局部的原始 XYZ 调查，不建立四相位完整栅格、不计算新法向、不重建角点。A/B/C 是原任务列出的典型调查准入：三条强 Raw 边，或强 Legacy/post-B2 加两条强 Raw 边及剩余独立结构，或满足独立 enclosure 的真实 cross-deck/缺测分支。没有启用只凭名义边数放行的 D 草案。

对于已经观察到但仍有歧义、具有独立结构提名且能容纳原物理断面的查询，共享 `FinalBoundaryRefiner` 可在同一个精修预算内先完成局部物理侧测量，再让 Probe 读取标量缓存并重新应用原准入。该步骤不构建栅格或角点，真实 Raw 面、局部实测高度和原断面空间共识不足时不写入强边。法向仍是此前成对表面、高度及结构测量不能唯一解释时的最后回退，耗时与计算点数单列，不隐藏在 Probe 的零法向计数中。真实矩阵说明这条复用路径尚未恢复全部召回，不能据此放行生产。

候选按物理区域和不同证据路径轮转；先测可容纳原有独立断面的闭合，跨越内部连续结构的外围替代排后。没有固定 Top-K 或固定舱数。共享精确 Raw 断面、连续测量、侧拟合及四相位栅格缓存；缓存开关不改测量坐标或验收门。

`VesselMeasurementContext` 共用完整 Raw UVZ、排序 U/V 索引、栅格、providers、剖面、边模式和面缓存。searchsorted 提取原始索引，包含重复回波且保留原始顺序；不对最终 Raw 降采样。

每个 side section 一次取点、排序，再在剖面视图中检测 robust 有符号变化。相邻锚点复用不可变 Raw 序列的精确顺序统计索引，保留每个窗口的原始点、开闭边界、NumPy 线性插值顺序和阈值比较；整数 rank 只表示原值顺序，不分箱高度、不采样、不合并站位。索引缓存以 64 MiB 约束存储，超过存储预算回到原 NumPy 计算。该方法依据 [range quantile 研究](https://arxiv.org/abs/0903.4726) 与 [wavelet matrix](https://users.dcc.uchile.cl/~gnavarro/abstracts/is14.html)；效果以本项目真实窗口测试为准。每模式只做少量真实成对回波与连续测量，保留原来的 0.05 m 分辨率；模式不直接平均。四个 phase 只重复 raster，Raw section、连续测量和高度统计共享。旧逐站全扫描保留作反证比较，不在 V2 生产路径调用。

成对表面和高度能唯一确定边时，不计算精修法向。面回退使用完整三维邻域，并缓存法向/面证据；8192 只是内存和中断批次大小。冻结 Legacy provider 为维持原证据输出，仍有原来的法向资格计算，诊断明确其不计入精修法向计数；不能宣称全链法向已完全惰性化。

局部多高度甲板保留各个合格的实测平面族，不把全船中位高度指定为甲板。必要的面回退可使用局部已观察到的 deck-to-lower 剖面与真实三维法向面，仍逐个满足原有独立物理断面、实测点数和高度落差要求；缺测与稳定第二模式不填补。批量分位数计算保留原剖面采样、插值、面位置和拒绝条件。法向规范排序的点索引显式映射回原始输入索引，防止把排序序号误当作船体归属证据。

完整实测面仍满足原有平面点数、垂直跨度及断面要求；其核心来源连接用同一面上的真实法向点和原线支持点数/跨度核对，不把核心标签子集再当作独立平面拟合。连接成立不等于未知上下文归属已确认。栅格提出其他位置时，已测得的三维墙面不能被附近地板台阶替换后继续沿用墙面来源。当前装料场景的高度角色耦合、缺测第四边与完整开口覆盖仍是未解决项。

混合来源的 section 在同一物理 line family 内作稳健空间共识，检查支持量、占比、跨度、残差和倾角。单异常为 `OUTLIER_SECTION`；两个稳定分离的线模式才是 `MULTIMODE_BOUNDARY_CONFLICT`。高度/BEV 不冒充三维钢面，货物轮廓、船舷外沿和高平台还需 opening-side 极性及近低区/远 deck 角色核对。

明显向内和向外移动都需原有独立物理支持，检查倾斜后端点及实际交点。不足则回到保守原边，明确风险和 uncertainty；`CONSERVATIVE_AXIS_LINE` 不是实测钢边。四线求交保留实测斜率，不强压轴对齐矩形；点线 uncertainty coverage 不充当钢内沿。

## 预算、输出与验收

候选采用协作式执行片：一次连续访问最多约 5 秒，并与其他待处理物理区域分享剩余阶段时间。数值原语在既有协作检查点让出；实际不可中断调用的超限仍如实记录。让出为 `DEFERRED_PERFORMANCE`，不作为几何拒绝，完成的角色侧证据和原始测量缓存保留。下一物理区域先得到访问，之后可继续未完成候选。累计候选时间与最长连续访问时间分别输出，阶段总预算仍为 20 秒。该执行片不改变 Raw XYZ、几何分辨率或物理验收门。

V2.2 首先增加性能法证，不改变本节物理门。`precision_scheduled_count` 计入等待调查的全部候选；`precision_started_count` 包含已经开始 RawProbe 或共享角色调查的候选；`precision_completed_count` 仅指完整精修器返回，不代表几何通过。`precision_timeout_count` 记录实际被预算中断的候选，`precision_deferred_count` 记录尚无完整精修结果的候选。兼容字段 `precision_query_count` 仍只统计完整精修尝试，不能用它解释整个精修阶段的耗时。

每个候选保留候选/物理区域身份、累计耗时、角色/剖面/Raw 边搜索/高度/法向/栅格/拟合/角点分项、超时阶段和已完成的逐边工作。直接分项为扣除子调用后的独占时间，另存包含子调用的时间，防止重复相加。预调查被中断时仍保存这些记录。法证 cProfile 的开销单列，不作为冷进程耗时验收。

阶段目标为 preprocess 3 s、berth 2 s、recall 10 s、validation 5 s、precision 20 s、render 5 s。核心为绘图预留 5 s，总目标 60 s；精修和法向批次协作式检查预算。单个不可中断数值调用仍可能越限，必须报告实际值，不能因此写性能门通过。

超时保存已完成结果和 `proposal_registry / physical_candidate_registry / precision_attempts` 的全部提案/尝试，不清空结果目录。Profiler 分开报告每候选、每侧及分项时间，剖面/模式/连续测量/空间查询与法向计数。

两张中文图保留完整原始场景、最终复核对象、角点坐标和舱内长宽；拒绝水面与未精修提案不画作最终舱框。`05_hatch_corners.json` 的 `.2` 契约从同一最终四线交点导出原始输入 XY；角点 Z 使用同船局部围板/甲板上沿的实测 Raw 平面与近角点支撑，保留高度不确定性和点索引身份。局部高度无唯一测量或相邻边缺少独立支持时 Z 为 null；Z 不反向参与检测或修改 XY。保守边和缺测推断仍有明确状态。

V2 始终 `XYZ_ONLY`：Intensity 只记录状态，不创建 scorer、不跑 intensity edge 或第二套融合几何；历史权重不改调。恒值/近恒值设备信号如实标记。

没有独立钢内沿 Golden，始终 `STEEL_EDGE_CERTIFIED=NO`。真实门同时检查覆盖、外部误检、逐边支持、历史回归与耗时。正常退出、数量和合成三舱通过不能代替真实召回；Normal6、V2 单调回归和 SITE 仍有未完成项，见测试与验收说明。
