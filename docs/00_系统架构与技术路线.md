## 当前职责与技术路线

当前交付是单帧开舱候选与人工复核工具。Scene Perception 输出 `VesselHypothesis[0..N]`，每船可有 `HatchProposal[0..N]`；开发集 1～3 舱是验证覆盖，不是发现容器的硬上限。连通域仅是空间分组原语，不等于船舶语义。

```text
PCD / ROS2 PointCloud2
  → transport-neutral PointCloudFrame + input validation
  → B1 once → immutable SceneEvidenceContext
  → vessel-local UVZ height / Raw3D / BEV / enclosure recall
  → observed exterior-low connectivity + vessel containment
  → opening / deck-ring topology validation
  → symmetric four-side Raw XYZ FinalBoundaryRefiner
  → final line intersections + coverage guard + uncertainty
  → geometry review + optional intensity evidence
  → two images + admission JSON + summary [+ snapshot]

optional legacy comparison: Height → structure → R2F/R2G → B4/B5
```

现场入口为 `ros2/ship_scan_once.py` 和 `perception/cli.py`，前者只负责图发现、QoS 和一帧采集。PCD、PointCloud2 codec 与算法均不依赖 ROS runtime。生产链先完成逐船召回；旧 R2F/R2G/B4/B5 作为显式可关闭的比较证据，不限制局部候选是否存在。独立链已设置单舱、多舱、多船及刚体变换反证；真实船泛化与弱边精度仍需独立数据验收。运行中的研究原语和旧比较依赖继续保留，不能按阶段名删除。

后续产品集成继续遵守冻结职责：严格解码 → 可信目标船 seed/ROI → Geometry / optional legacy CNN proposals → candidate union / joint hypotheses → per-hatch local deck → opening-side 3D evidence → boundary fusion → Hatch/Partial/Unresolved → 固定 Ship Frame。当前 ROS 工具不宣称已完成产品、跟踪或控制集成。

Target Selection 必须用可追溯外部作业信息确认一个目标船，不能以面积最大、距离最近或绝对 Y 最小自动选择。没有可信 seed 时保持 `TARGET_VESSEL_UNRESOLVED`。Global Deck、全图单一低洼连通域、固定窗口和 CNN 矩形不能作为物理真值或产品必需前置。

## 输入、物理边界与证据

运行时允许 Raw XYZ、当次测量 intensity、可信作业范围、雷达外参和必要平台/传感器位姿。评分 Hatch ROI、人工已知舱数、隐藏 GT、历史 PNG 和审查 JSON 不进入检测求解。legacy hold_detector 仅是只读资产参考，不依赖其源码或权重。

物理 opening-side 边界是面向舱口开口内侧的真实结构转折。Cargo 轮廓/坡脚、Wharf、船外轮廓、横梁表面、驾驶室、固定高度等值线不能冒充 Hatch steel boundary。

证据类型保持 `OBSERVED_PROFILE_BREAK / OBSERVED_3D_FACE / OBSERVED_BEV_CONTOUR / INFERRED_GEOMETRY / INFERRED_VESSEL_PRIOR / HISTORICAL_MODEL / OPERATOR_CONFIRMED / UNKNOWN`。Observed 必须有原始测量支持，BEV 只能辅助；推断、几何闭合和历史不能改名为观测。Historical 附来源与年龄，静态缺点默认 UNKNOWN，不能凭空声称 OCCLUDED。

Intensity 不新增钢边证据类型，只辅助已有几何候选评分与诊断，不单独生成舱，不绕过结构、角色与角点门。首次全遮挡且无历史时，PRIOR_ONLY、OPERATOR_CONFIRM_REQUIRED 或 INSUFFICIENT_OBSERVATION 是合法结果，不能承诺恢复隐藏钢边。

## 坐标与输出契约

变换统一 `T_A_B`：将 B 坐标表达转换到 A。C++ 核心使用 Eigen::Isometry3d，位姿 double，局部点云可为 float；全部舱属于固定 Ship Frame B：

```text
P_hatch^W(t) = T_W_B(t) * P_hatch^B
```

不允许每个舱独立漂移或在 pose 无效时伪造当前世界精确几何。当前现场 JSON 为输入消息 XY 米制坐标，逐船 UV 轴在诊断中；这不是已确认作业船的 Ship Frame 模型。`best_estimate_boundary_xy` / `boundary_xy` 保存最终四线交点，`review_coverage_boundary_xy` 保存不确定性覆盖；覆盖范围不是实测钢边，图中明确用不同线型表达。

冻结 UV 轴是共同坐标基准，不代表强制四条实测边与该轴平行。边线可保留相对该基准的观测斜率，角点按直线求交后仍通过同一坐标变换返回输入 frame；这不会给各舱建立独立漂移的姿态。

产品每舱契约至少包含 ID、ship-frame polygon、observation_status、edges、confidence/ambiguity 和 reason；逐边包含 ID、visibility、evidence_type、opening_side_status、observed_support、uncertainty 和 reason。当前 PARTIAL/UNRESOLVED 审查状态不等于商业确认。

合法失败包括 NO_CONFIRMED_HATCH、HATCH_COUNT_AMBIGUOUS、TARGET_VESSEL_UNRESOLVED、LOCAL_DECK_UNRESOLVED、INSUFFICIENT_OBSERVATION、POSE_INVALID、OUT_OF_SCOPE。证据不足保持 fail-closed，不为完整矩形补造钢边。

## 集成与变更

识别先于跟踪联动；控制、PLC、抓取规划、Web、RTK/GNSS、新 ES-EKF、深度语义主干、自动作业船选择和多帧融合不属于当前现场入口。V1.4 代码与正式 Tag 保留，历史验证不等于当前 SITE 通过。

主链改序、核心职责、证据类型、坐标树、split/holdout、验收门、模型主干或 V1.4 冻结路径变化，必须先有明确评审。本轮用户已明确授权逐船主链重构与 ROS2 迁移；原有物理阈值、强度权重、验收门、GT 隔离和 V1.4 frozen 约束继续生效。
