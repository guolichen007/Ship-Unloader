## 核心结论（先看这里）

1. **`FIRST_BAD_STAGE = DECK_REFERENCE_AMBIGUOUS`**：六场景关键边（baseline 所选 node 的 perimeter 段）的第一失败阶段一致是 `estimate_segment_deck` 的多平面歧义，而不是 profile/face/line 模型或轮廓摆放。
2. **`DECK_COAMING_HYPOTHESIS = SUPPORTED`**：歧义段的外侧支撑带里，主导几何模式确实是「一个宽水平面 + 一个较窄、更高、更贴边界的邻接平面」。按**几何口径**（宽低 + 窄高邻接，不管竖直连接面是否被直接观测到）在所选 node 上占 **69%–100%**；按**严格口径**（还必须存在支持高度跨度的竖直 raw return）占 **42%–88%**。高度差中位数 0.56–0.87 m，落在围板顶的合理范围。
3. **但这不是全部**：次要模式还有「较窄平面反而更低」（NARROWER_PLANE_NOT_ELEVATED）、「抬升平面反而更靠外」（ELEVATED_PLANE_NOT_CLOSER_TO_BOUNDARY）、以及「同高度不同倾角的两片」（HEIGHT_DIFFERENCE_BELOW_AMBIGUITY_GATE）。4-16 的严格口径只有 42%，说明其外侧带常被倾斜/货料面碎片化，竖直围板墙往往没有直接回波。
4. **`NEXT_ALGORITHM_DECISION = MULTI_PLANE_STRUCTURAL_INTERPRETATION`**：保留多个水平面并分类其几何角色（broad support → DECK_REFERENCE_CANDIDATE，narrow elevated adjacent → STRUCTURE_TOP_CANDIDATE，其余 → competing surface），而不是简单在多个面里强制挑一个 Deck，也不是单独针对围板写死逻辑。这正是「多水平面结构解释」的方向。

## P1-A 段甲板歧义组成

`estimate_segment_deck` 在外侧最多 4 m 带内找多个近水平平面，独立面门槛是「法向角差 > 3° 或锚点高度差 > 3×0.05 m」。因此歧义可来自**高度差**（deck + 抬升面）或**倾角差**（同高度两片不同倾角）。P1-A 对每个 `SEGMENT_DECK_AMBIGUOUS` 段保存全部候选平面的 normal / anchor height / support count / outward width / along coverage / residual p50,p95 / 法向距离 min,p50,p95 / 到段中线的中位距离 / along span，并对每对合格平面输出高度差、法向角差、raw 支撑重叠、相对宽度、相对支撑数、相对边界距离、竖直连接面支撑数与跨度。**不自动给平面命名 Deck / Coaming**，只在组合证据满足「宽低面 + 窄高邻接面 + 竖直连接」时标 `DECK_COAMING_LIKE_PAIR`，否则 `UNKNOWN_PAIR`。

| 场景 | 所选歧义段 | 几何口径 coaming-like | 严格口径（含竖直连接） | coaming 高度差中位 m |
| --- | ---: | ---: | ---: | ---: |
| 08-01 | 16 | 16 (100%) | 13 (81%) | 0.61 |
| 08-08 | 8 | 7 (88%) | 7 (88%) | 0.60 |
| 4-16 | 26 | 18 (69%) | 11 (42%) | 0.87 |
| 6-8 | 4 | 3 (75%) | 1 (25%) | 0.40 |
| 7-16 | 35 | 29 (83%) | 25 (71%) | 0.56 |
| 8-22 | 21 | 19 (90%) | 15 (71%) | 0.63 |

全节点口径（含非所选 node，`decision_matrix_p1.json`）几何 coaming-like 占比 0.65–0.89，严格口径 0.38–0.66。**4-16 是几何口径最低、且严格口径与几何口径差距最大的场景**：其外侧带候选平面常多达 10–15 个、高度散布约 2 m（例如 `l02-c0002-s000-g001` 的 15 个候选高度 −6.77 到 −8.00 m），呈现倾斜/碎片化表面，而不是干净的「deck + 围板顶」两平面。非 coaming 的失败原因以 `ELEVATED_PLANE_NOT_CLOSER_TO_BOUNDARY`（抬升面更靠外）与 `NARROWER_PLANE_NOT_ELEVATED`（窄面更低）为主，其次 `HEIGHT_DIFFERENCE_BELOW_AMBIGUITY_GATE`（纯倾角歧义）。

对用户假设的直接回答：**4-16 的 28 个歧义段（本次环境计 26 个，见「环境敏感性」）里，几何上约 69% 呈现「宽低 + 窄高邻接」的围板式组合，但只有约 42% 同时有竖直连接面回波；其余约三分之一是倾斜/碎片化或窄面更低的非围板模式。** 即「deck+coaming 被误判歧义」在几何上成立且为主，但系统把多种「多水平面」情况一律丢弃，围板只是其中一类。

## P1-B 弱标注 Oracle band probe

对五个 `PARTIAL_SINGLE_HATCH` 场景的弱标注框四边，沿边法向做 ±0.5 / ±1.0 / ±1.5 / ±2.0 m 诊断扫描（1.5 m 对应当前 `boundary_search_m`，仅法证，不进产品配置），每个 offset 用 Raw XYZ + 现有 `estimate_segment_deck` + `_profile` + face 校验 + `_fit_line`。语义固定 `WEAK_LABEL_ORACLE_DIAGNOSTIC_ONLY`；8-22 无标注不跑。

Oracle 在 4/5 个有标注场景能找到**部分**结构线，但都只命中 1–2 条边、且多落在非零 offset；没有任何场景在弱标注四边上形成完整周界。08-08 全空与其弱标注 IoU 0.295（弱标注远离真实舱）一致。结论：真实边附近确有现有 profile/face 能检出的结构，但稀疏且位置偏，**不是轮廓摆放的单一失败**——首要阻塞仍是段甲板歧义让 profile 根本未执行。

## P1-D 高度轮廓几何审计

轻量法证：每 node 输出 raw 轮廓点数、简化顶点数、段数、段长、段朝向、转角直方图。4-16 所选 `l02-c0002` 为 512 raw 点 / 30 段（段长中位 3.57 m），7-16 所选 `l02-c0001` 为 1102 raw 点 / 65 段（段长中位 4.03 m），8-22 所选 node 仅 5–13 段但较大非所选 node（如 `l02-c0004`）达 45 段。转角直方图显示这些轮廓**都不是干净四角矩形**：7-16 所选 node 在 ±90° 转角 bin 只有 15/8 计数，大量非直角转角；4-16 所选 node 为 8/8。轮廓本身不规则、切分过细，使外侧支撑带频繁跨入非甲板表面——与 P1-A 看到的碎片化一致。

## FIRST_BAD_STAGE 与下一阶段决策

按冻结决策表：

- `FIRST_BAD_STAGE_BY_SCENE`：六场景一致为 `DECK_REFERENCE_AMBIGUOUS`（6-8 同时有大量 `PROFILE_NOT_EXECUTED`，其 deck 未解是第一因）。
- `DECK_COAMING_HYPOTHESIS = SUPPORTED`（几何口径主导，严格口径部分证实；不是 100%）。
- `NEXT_ALGORITHM_DECISION = MULTI_PLANE_STRUCTURAL_INTERPRETATION`：保留多个水平面并分类几何角色，而不是在多个面里强制挑一个 Deck、或单独写围板逻辑。理由：① 歧义确由多水平面构成，围板式组合是主类但不是唯一类；② 竖直围板墙经常无直接回波，无法靠「挑出 deck」单值解决；③ 用户已明确倾向多水平面结构解释而非降低 `segment_deck` 阈值。

具体到各场景的下一步线索：4-16 先查「抬升面更靠外 / 窄面更低」的倾斜货料面污染；8-22 的三个所选候选高度定位正确但周边面同样碎片化；08-08 的树内更优后代（IoU≈0.723）仍是候选选择问题；6-8 / 7-16 的 `PROFILE_NOT_EXECUTED` 与碎片关联需在解除 deck 前置锁后再评。以上均为法证假设，不构成已获批准的新算法或真实标定通过。

## 环境敏感性说明（重要）

本次在会话沙箱（Python 3.10 / numpy 2.2.6 / scipy 1.15.3）运行，与冻结环境（Ubuntu 20.04 / Python 3.8 / numpy 1.x / scipy 1.x）不完全一致。`estimate_segment_deck` 内的 `np.linalg.lstsq` 与 `np.percentile` 在不同版本下会产生微小数值差异，导致**贴近歧义门槛的段在 RESOLVED / AMBIGUOUS 之间翻转**：六场景段级 deck 状态与 S4-P0（冻结环境）相比差异为 08-01 13/193、08-08 14/102、4-16 21/242、6-8 9/164、7-16 9/135、8-22 9/127（约 5–14%）。因此本报告的**逐段精确计数**（如 4-16 所选 26 vs S4-P0 的 28）需以 Ubuntu 20.04 重跑为准；但**定性结论**（几何 coaming-like 占比 65–89%、高度差中位 0.56–0.87 m、FIRST_BAD_STAGE=DECK_REFERENCE_AMBIGUOUS、NEXT=MULTI_PLANE_STRUCTURAL_INTERPRETATION）对这几段的翻转不敏感。正式发布前应在冻结环境重跑 `baseline_006_p1` 与评估器。
