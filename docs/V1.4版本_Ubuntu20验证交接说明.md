# V1.4 Ubuntu20 统一验证交接

## 当前边界

先完成统一代码审查，再由 Ubuntu20 ClaudeCLI 验证用户收到的精确 `IMPLEMENTATION_SHA`。本功能分支不合并 main、不创建 V1.4 基线标签、不进入 V1.5。

`BASE_SHA=06af2d66262afd828edf2eef72b6ce1bc6969797` 是用户指定开发起点；它不代替原始 M0 正式通过报告。当前 `ORIGINAL_M0_EVIDENCE=PENDING_ARCHIVE`，不得补造证据。

## 精确 SHA 与全新构建

现有工作树有未知修改时先保存用户文件，不能用 reset/clean 强行清理。把交付消息中的完整 40 位 SHA 填入下列命令；不以分支名替代验证目标。

```bash
cd /你的路径/Ship-Unloader
SHA='<IMPLEMENTATION_SHA 的完整 40 位值>'
test -z "$(git status --porcelain)" || exit 1
git fetch origin feature/v1-4-ship-track-map
git checkout --detach "$SHA"
test "$(git rev-parse HEAD)" = "$SHA" || exit 1
test -z "$(git status --porcelain)" || exit 1
bash ship_perception/scripts/validate_ubuntu20.sh \
  --sha "$SHA" \
  --base-sha 06af2d66262afd828edf2eef72b6ce1bc6969797 \
  --cmake /usr/bin/cmake --ctest /usr/bin/ctest --jobs 2
```

首次获取可用 `git clone git@github.com:guolichen007/Ship-Unloader.git`。系统依赖安装命令见[构建说明](../ship_perception/README.md)。验证要求 Ubuntu20、GCC9、CMake3.16、Eigen3.3.7、PCL-ON；记录 PCL 实际版本与头文件路径。默认优先系统 Eigen 配置，不能以 pkg-config 的另一个版本代替实际编译依赖证据。

脚本每次新建 `validation/<SHA>/<UTC-run-id>/build`，不删除历史记录或复用缓存，构建本身离线。按顺序执行验收器反例、生成器/PCD 自检、真实后端、地图安全、原 G5 harness、G1～G7 Quick，然后运行 **Full Acceptance**。PCL GICP 每场景/种子首对帧只作对照，其精度不阻塞版本。

Full 为两后端 × 17 场景 × 3 种子 × 200 帧；闭环与相邻帧 benchmark 独立评分，初始化帧单列。场景过滤或 Quick 结果不能替代 Full。至少同一个后端贯穿全部 11 个正常场景及种子达标。

## 必须审查的证据

- 构建日志、CTest 清单及日志、实际依赖文件，精确 SHA 和干净工作树审计。
- `v14_full/report.json` 的两个后端比较、合格集合、编译 SHA、配置哈希与产物校验值。
- `pose.csv` 中无效帧、末帧误差、每帧静态 P95 与样本数，不能仅看总体均值。
- `quality.csv` 中真实执行、收敛、失败原因、数学检查、共同质量、H 可用性及公平请求指纹。
- `map.csv` 中帧开始目标 revision、提交后地图和候选 revision；拒绝帧不得污染状态。
- `timing.csv` 的补偿/配准/地图/总耗时；开发机数值不能承诺现场实时性能。
- 捕获范围、坐标自由度诊断、参考地图及抽样累积观测 PCD；后者含动态点。
- GT 隔离、非法输出、合法错误位姿、候选污染、首帧暂态隔离、遮挡、容量及参考支撑不足安全断言。

主要日志在运行目录内，统一结构化报告为 `report.json`，中文摘要为 `验证摘要.md`。原始产物保留在 Ubuntu；正式报告归档时记录路径及哈希，不把报告脚本的建议判定直接当成独立结论。

```text
V14_QUICK=
V14_FULL=
GICP_ALL_REQUIRED_SCENES=

ORIGINAL_M0_EVIDENCE=PENDING_ARCHIVE（或真实已归档证据引用）

FINAL_DECISION=

```

CODE_FAIL 返回 Codex 修复并产生新 SHA；Ubuntu 对新 SHA 重新 clean build 和 Full。TEST_FAIL 先复核测试设计，不能删失败样本或降低门槛。ENV_FAIL 保留环境证据，保持 Ubuntu20 目标。现场缺失持续 SITE_PENDING。

只有统一代码审查、同一 SHA 的正式验证均通过且报告归档后，才可由用户决定合并 main 并固化 V1.4 基线；本次交付停在“代码实现完成，等待统一代码审查”。
