## 范围与架构边界

本阶段提供 Python 静态单帧参考实现，输入为原始 PCD，输出为 `RAW_INPUT_FRAME`。它不接入 V1.4 跟踪、PLC 或现有 C++ Production 主链。现有 Architecture Freeze 中的 Ship Frame 与目标船 seed 契约仍适用于后续产品集成；产品集成前须完成独立架构评审。当前实验不读取 Hatch GT ROI 或人工已知舱数。

`ship_perception/r1_static/` 不导入 `measurement/`、旧 `hold_detector` 源码或 CNN 权重。数据目录中的历史 PCD 只通过 manifest 定位，解码入口唯一为 `ship_perception.tools.v15_pcd.decode`。

## 算法链

1. 严格解码、校验有限 XYZ，并记录文件 SHA256、点数和 Raw bbox。
2. 自有 `R1HeightGrid` 在既有 `coarse_voxel_m` 与 `candidate_voxel_m` 上统计 count、q10、median、q90、min、max、occupancy。格网从当前点云最小 XY 起始，避免绝对 Y 依赖。
3. 多尺度候选用局部环带平均高表面与 cell q10 的落差形成 seed，连通并跨尺度合并。它不预设候选等于一个舱。
4. 每个候选的外环进行重力一致的随机初始平面搜索，随后以法向、点面残差、高度连续性和空间连通性生长局部 patch。Huber 只精修已选支撑；竞争平面、支撑不足或单侧支撑均失败关闭。
5. 相对候选 Local Deck 寻找独立 lower-return 连通域。同一个候选允许分出多个 opening；这一阶段的轮廓仅作 Profile 的初始位置。
6. 对粗边按物理长度产生横断面，在原始 3D 回波中寻找 deck-to-lower break 与竖直 face；按真实类型记录 `OBSERVED_PROFILE_BREAK`、`OBSERVED_3D_FACE` 或两者。稳健拟合后的线段端点只覆盖实际支撑区间。
7. 四边都有可连接的观测支撑时才给出 `COMPLETE_OBSERVED` polygon；缺边保留 `PARTIAL` 或 `UNRESOLVED`，不补矩形第四边。
8. 对候选 opening 构造重复冲突，枚举 0～3 舱合法组合，按局部甲板、观测边、覆盖长度与残差打分。分数近似时返回 `HATCH_HYPOTHESIS_AMBIGUOUS`，同时保存前两种假设。

当前 `PlanarRegionGrower` 为轻量实现，不引入 Open3D、CGAL 或额外运行时模型。真实数据失败必须原样保留；不得用已知舱数、文件名或绝对 Y 改判。

## 单场景运行

```bash
python -m ship_perception.r1_static.run \
  --input Ship-Unloader-Data/legacy/hold_detector/detect/test/<scan>.pcd \
  --output-root Ship-Unloader-Work/r1_static \
  --run-id baseline_001 \
  --observed-only
```

结果位于 `Ship-Unloader-Work/r1_static/<run_id>/<scene_id>/`。再次使用同一 `run_id/scene_id` 会拒绝覆盖已有 `result.json`。

配置沿用 `ship_perception/config/v15.json`。可用 `--override boundary.profile_step_m=0.04` 或 `--override-file Ship-Unloader-Work/experiment.json` 做实验；覆盖文件采用扁平的 `"section.key": value` JSON 对象。`evaluation` 节不可覆盖，不能改用另一份主配置。解析后的配置还通过现有 `configure_v15.py` 冻结契约检查。每次写出 `resolved_config.json` 与规范化 `config_hash`，便于重现；实验覆盖文件不提交。

## 结果与颜色

每场景保存 `result.json`、四份彩色 PLY、`proposal_debug.json`、`profile_debug.json`、`timing.json`、`resolved_config.json`。JSON 版本为 `ship_perception.v15r.static_result.1`，禁止 NaN/Infinity。时间分解为 decode、proposal、local_deck、boundary、hypothesis、visualization 与 total。输出中心及线段在 Raw 坐标；`PARTIAL` 的 `polygon_raw` 为 null。

| 颜色 | 含义 |
| --- | --- |
| 灰 | 原始点云 |
| 绿 | Local Deck 支撑 |
| 紫 | Proposal 范围 |
| 红 | 已确认 opening 内部 |
| 蓝 | Profile Break 观测边 |
| 青 | 3D Face 观测边 |
| 白 | 四边相交且有观测支撑的角点 |
| 黄 | 粗 opening seed 中心，非钢边证据 |
| 橙 | 部分观测的 opening 范围 |

PLY 为 little-endian binary，字段为 `x y z red green blue`，可直接用 CloudCompare 打开。中心点只供定位，不能代替独立物理边线验证。

## 失败状态与已知限制

Local Deck 可返回 `LOCAL_DECK_UNRESOLVED` 或 `LOCAL_DECK_AMBIGUOUS`；场景可返回 `NO_CONFIRMED_HATCH`、`HATCH_HYPOTHESIS_AMBIGUOUS` 或 `RESOLVED`。真实运行异常由批处理写 `failure.json`，不转写为零舱成功。

- 只做静态单帧；没有 V1.4 位姿或跟踪。
- 坚持 Observed-Only；遮挡边不补全，缺点默认不是 `OCCLUDED`。
- 同一 Proposal 内多个 opening 暂时共用 Candidate Local Deck，输出限制标记。
- 以 lower-return 为首要 seed；高于 Deck 的 Cargo 可能掩盖真实 opening，必须人工查看未解析场景。
- Python 结果用于算法审查与人工复核，不构成商业 Golden 或 C++ parity 证明。
