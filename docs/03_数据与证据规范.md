## V2 现场参考与候选追溯

码头参考是现场先验，不是船先验。保存实际 `frame_id`、码头直线、朝水方向、工作区和测量来源；不得保存船尺寸、舱数或舱角坐标。操作员选择的某次船体 ROI 只能作为该次输入派生记录，不能冒充永久码头标定。无可靠参考的多船保持歧义。

每次 V2 结果保存原文件 wire SHA、有限点 semantic SHA、原始点索引身份、配置身份、Git SHA 与执行源哈希。无损解压保留全部原值及点序；原始文件不改动。`proposal_registry`、`physical_candidate_registry` 和 `precision_attempts` 保留候选来源、边界、状态和预算中断前的证据，未精修提案不写成认证钢边。

V2.2 显式输出 `git_head_sha / git_worktree_dirty / git_diff_sha256 / runtime_source_sha256 / config_sha256 / input_sha256`。脏工作树的输出目录额外保存 `runtime_patch.diff`，包含尚未加入 Git 的新源码；补丁摘要必须与结果一致，否则不发布该结果目录。Git 的未刷新 stat 缓存不作为内容变化的唯一依据。不同运行源码身份不能组成同一性能验收组；缓存 A/B 两组的源码差异必须单独归档。

Legacy Golden 位于测试夹具，只保存输入与完整 proposal/evidence 哈希等小型元数据，不含客户 Raw 点云或四角 GT。比较工具从私有数据根读取匹配输入，运行时不加载这些 Golden。最终边精度仍需独立标注的 per-side GT、遮挡片段、reviewer、annotation version 与 PCD SHA，不能拿 Legacy proposal Golden 替代。

冻结合同分为 V1_4_FROZEN、LEGACY_B2_CORE_FROZEN 和 LEGACY_FULL_CHAIN_REFERENCE。B2 原核心哈希与适配符号基准分别记录，依赖清单须同时有导入关系、实际调用和真实 Golden 证据；不能从旧清单直接删文件解决冲突。旧完整链哈希继续保留，批准的 S4 变化单列 REFERENCE_CHANGED_EXPECTED，不改写旧参考为当前值。

S4→V2 审计保存实际观测、侧族坐标基准与观测区间、节点内区单元、同船归属、CONNECT/SPLIT/AMBIGUOUS 关系及提名归属来源。高度组范围不是实测钢边，source_point_indexes 缺少精确 inlier 映射时保持空值，不以邻近点伪造测量支持。历史图坐标只在结果写完后的隔离覆盖审计读取，不参与侧族、图连接、范围或 rho 选择。

2026-10-30 扩展回跑对 5 份多船原始扫描保存靠岸船裁剪审计。两份新扫描沿用已有操作员空间 ROI，并重新核验原始点；另外三份按同一图示岸侧的完整船体原始索引裁剪，排除其他已分辨船体的点。记录原始/派生 wire SHA、点数、来源索引及其哈希、ROI 依据和 XYZ/intensity 逐位一致性，原始 frame 不变。操作员 ROI 不冒充实测永久码头配置，裁剪时间不混入同输入算法加速比较。

大体积 `03_results.json` 采用严格紧凑 JSON 和原子替换；仅去掉缩进，保留全部字段、浮点值、Unicode 和拒绝非有限数的行为。小型四角与失败 JSON 继续保留缩进。坐标副本须核验 `source_result_sha256`，未决搜索区域另列坐标及 `SEARCH_REGION_NOT_STEEL_BOUNDARY`；其角点 Z 保持 null，不能与最终复核对象或实测钢边混用。

## 3. 原始资产不可修改原则

Raw 数据：

- 不覆盖；
- 不原地重采样；
- 不原地修复；
- 不改名后冒充新样本。

派生数据必须保留：

```text
source_sha256
tool_version
command
config
output_sha256
created_at
```

## 4. 物理扫描去重

文件数不等于物理扫描数。

去重至少记录：

```text
byte_sha256
canonical_xyz_sha256
point_count
bbox_min_xyz
bbox_max_xyz
centroid_xyz
```

PCD / PLY 仅点数一致，不足以证明同一物理扫描。

如编码精度不同，可补：

```text
NN_error_p50
NN_error_p95
NN_error_max
```

禁止通过自由 ICP 对齐后再声称原始数据相同。

## 5. Scene Contract

层级固定：


## 7. 标注级别

### Development Label

用途：

- Proposal recall；
- Hatch count；
- merge / split；
- duplicate；
- coarse matching。

不得承担商业泛化或厘米级边界声明。

### NEW_GOLDEN

必须满足：

- 新数据；
- 独立物理 opening-side GT；
- 双人复核；
- 明确 FOV；
- 明确目标船；
- 明确边可见性；
- 与算法开发过程隔离。

### NEVER_SEEN_SEQUENCE

用于最终泛化：

- 新船；
- 新时间序列；
- 开发者未见；
- 保留原始时间和传感器链。

## 8. Review Governance

必须区分：

## 9. Holdout 治理

- 只能做历史诊断；
- 不再承担商业盲测；
- 视觉暴露必须永久登记；
- 不得反复调参后继续称 sealed。

最终商业验证：

```text

+

NEVER_SEEN_SEQUENCE
```



## 当前输入适配与离线文件

正式 IO 支持见[ROS2 现场说明](02_ROS2现场一键识别运行说明.md)。`io/pcd_source.py` 支持 scalar ASCII、binary 与无损 binary_compressed，保留 FLOAT32/FLOAT64 XYZ、原点序和源 intensity 精度；`io/pointcloud2_codec.py` 独立解析 ROS2 布局。压缩输入保留原文件 SHA、布局和无损解压身份；离线格式转换仍须记录逐点 parity。原始文件不可覆盖。

输入同时保存原始 wire/file SHA 与有序、规范化 XYZ/intensity 的 semantic SHA。相同 XYZ 不代表相同消息身份；来源、frame_id、时间戳和字段布局必须保留。`SceneEvidenceContext` 固定一次 B1 点归属，生产/比较分支复用同一身份，不重新解释船体归属。运行时不加载标注；历史 PCL 零尾字节例外单列在 `config/pcd_padding_contracts.json`，只含既有文件 SHA/字节计数授权，不包含几何或 GT。

正式结果使用 `config/hatch_once.schema.json`：五份文件原子落盘，可选 NPZ 快照；失败只写 `failure_*/failure.json`。结果记录 Git SHA、源码摘要、工作树状态、配置 SHA、数值库版本、QoS、各阶段耗时、逐船/仓/边诊断。`review_coverage_boundary_xy` 是不确定性复核范围，不能当作观察到的钢边。

独立四角文件 `05_hatch_corners.json` 使用 `ship_perception.hatch_corners.2`，保存来源完整结果的文件 SHA、识别软件/输入/配置身份和全部最终复核对象的原始 XYZ 坐标。XY 直接来自 `boundary_xy`，不重新拟合或裁剪图片；Z 是局部围板/甲板上沿的独立 Raw 测量，不是舱底、全船平均或布局补值。缺测为 null，另含高度状态、不确定性、Raw 支撑点索引身份和测量方法；保留组歧义、未决状态及防内裁风险，不能据导出对象数认证真实舱数。

图中 `P1/P2/P3/P4` 对应 JSON `C0/C1/C2/C3`，分别为 `U0/V0、U1/V0、U1/V1、U0/V1`。每角显示输入 XYZ（米，Z 缺测显示“未观测”），并以引线关联实际角点；标签避让只影响文字位置。`dimensions.length_m` 为两条 U 向边（V0、V1）的实长平均，`width_m` 为两条 V 向边（U0、U1）的实长平均；`side_lengths_m` 保留各边原始实长。计算使用最终四线交点的欧氏距离，适用于旋转、倾斜和非完全平行边，不使用 XY 轴向包围盒。两张图采用同一计算函数，显示三位小数；未决组尺寸仍只是组的复核外缘尺寸，不代表单舱尺寸或钢边精度。

独立精度标注采用 `config/hatch_golden.schema.json`，必须绑定原始 PCD SHA、坐标系、标注版本、四边内法向、可见性和忽略段。`ADJUDICATED` 至少两个不同 reviewer；DRAFT 数值结果不算正式验收证据。`evaluation/hatch_precision.py` 只在离线评分入口读取标注。当前 `hatch_golden_registry.json` 为 DATA_PENDING，不含虚构钢边。

人工确认的未开舱船可登记为本轮开舱评估范围外，不依靠文件名猜测；不将未决候选记为有效开口，不把范围说明作为 runtime seed、评分输入或钢边 GT。

当前场景与去重元数据继续保留在 `ship_perception/datasets/`；已有小型合成测试夹具按清单保留，不把客户数据伪装成夹具。推断/观测/历史身份按[架构](00_系统架构与技术路线.md)分开，失败及暴露记录不得删除。
