## 1. 数据根目录

```text

├── raw/
│   └── map/
├── legacy/
│   └── hold_detector/
├── annotations/
└── manifests/
```

该目录必须被 `.gitignore` 忽略，永不推送 Git / Git LFS。

## 2. Work Root

```text
Ship-Unloader-Work/
├── build/
├── validation/
├── logs/
├── reports/
└── tmp/
```

所有可再生成内容进入 Work Root。

## 3. 原始资产不可修改原则

Raw 数据：

- 不覆盖；
- 不原地重采样；
- 不原地修复；
- 不改名后冒充新样本。

派生数据必须保留：

```text
source_sha256
tool_version
command
config
output_sha256
created_at
```

## 4. 物理扫描去重

文件数不等于物理扫描数。

去重至少记录：

```text
byte_sha256
canonical_xyz_sha256
point_count
bbox_min_xyz
bbox_max_xyz
centroid_xyz
```

PCD / PLY 仅点数一致，不足以证明同一物理扫描。

如编码精度不同，可补：

```text
NN_error_p50
NN_error_p95
NN_error_max
```

禁止通过自由 ICP 对齐后再声称原始数据相同。

## 5. Scene Contract

层级固定：

```text
scan
└── vessels[]
    └── hatches[]
        └── edges[]
```

必须区分：

```text
visible_in_fov_hatch_count
whole_vessel_hatch_count
```

Partial-FOV 时整船总舱数可以为 `null / UNKNOWN`。

## 7. 标注级别

### Development Label

用途：

- Proposal recall；
- Hatch count；
- merge / split；
- duplicate；
- coarse matching。

不得承担商业泛化或厘米级边界声明。

### NEW_GOLDEN

必须满足：

- 新数据；
- 独立物理 opening-side GT；
- 双人复核；
- 明确 FOV；
- 明确目标船；
- 明确边可见性；
- 与算法开发过程隔离。

### NEVER_SEEN_SEQUENCE

用于最终泛化：

- 新船；
- 新时间序列；
- 开发者未见；
- 保留原始时间和传感器链。

## 8. Review Governance

必须区分：

```text
DRAFT
INDEPENDENT_REVIEW
ADJUDICATED
```

当前 Review A 已经进入远端文档，因此状态必须如实写：

```text
REVIEW_A_EXPOSURE=PUBLIC_REPO_DISCLOSED
```

以后不得再宣称 Review A 未公开。

Reviewer B 若要保持独立：

```text
REVIEW_B_REPO_ACCESS=NO
REVIEW_B_REVIEW_A_ACCESS=NO
```

## 9. Holdout 治理

旧 weak holdout：

- 只能做历史诊断；
- 不再承担商业盲测；
- 视觉暴露必须永久登记；
- 不得反复调参后继续称 sealed。

最终商业验证：

```text
NEW_GOLDEN
+
NEW_VESSEL
+
NEVER_SEEN_SEQUENCE
```

## 10. Ground Truth 隔离

Oracle ROI / Golden edge 只能进入：

```text
scoring/
oracle/
validation/
```

不得进入：

```text
runtime proposal
product config
training negative mining
target vessel seed
```

任何 GT 泄漏都必须记录。

## 当前输入适配与离线文件

ROS PointCloud2 支持见[现场说明](02_ROS现场一键识别运行说明.md)。`tools/v15_pcd.py` 严格支持其明确接受的 binary 布局，不默认支持 ascii/binary_compressed；额外尾字节按已有文件 SHA 契约授权，不能放宽到任意文件。一次离线解压不代表已发布通用压缩 PCD CLI；转换须保留原始 SHA、布局、点数、bbox、intensity 对齐并做独立 parser parity。

人工确认的未开舱船可登记为本轮开舱评估范围外，不依靠文件名猜测；不将未决候选记为有效开口，不把范围说明作为 runtime seed、评分输入或钢边 GT。

当前场景与去重元数据继续保留在 `ship_perception/datasets/`；已有小型合成测试夹具按清单保留，不把客户数据伪装成夹具。推断/观测/历史身份按[架构](00_系统架构与技术路线.md)分开，失败及暴露记录不得删除。
