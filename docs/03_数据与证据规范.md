```text

```

所有可再生成内容进入 Work Root。

## 3. 原始资产不可修改原则

Raw 数据：

- 不覆盖；
- 不原地重采样；
- 不原地修复；
- 不改名后冒充新样本。

派生数据必须保留：

```text
source_sha256
tool_version
command
config
output_sha256
created_at
```

## 4. 物理扫描去重

文件数不等于物理扫描数。

去重至少记录：

```text
byte_sha256
canonical_xyz_sha256
point_count
bbox_min_xyz
bbox_max_xyz
centroid_xyz
```

PCD / PLY 仅点数一致，不足以证明同一物理扫描。

如编码精度不同，可补：

```text
NN_error_p50
NN_error_p95
NN_error_max
```

禁止通过自由 ICP 对齐后再声称原始数据相同。

## 5. Scene Contract

层级固定：

```text
scan
└── vessels[]
    └── hatches[]
        └── edges[]
```

必须区分：

```text
visible_in_fov_hatch_count
whole_vessel_hatch_count
```

Partial-FOV 时整船总舱数可以为 `null / UNKNOWN`。

## 7. 标注级别

### Development Label

用途：

- Proposal recall；
- Hatch count；
- merge / split；
- duplicate；
- coarse matching。

不得承担商业泛化或厘米级边界声明。

### NEW_GOLDEN

必须满足：

- 新数据；
- 独立物理 opening-side GT；
- 双人复核；
- 明确 FOV；
- 明确目标船；
- 明确边可见性；
- 与算法开发过程隔离。

### NEVER_SEEN_SEQUENCE

用于最终泛化：

- 新船；
- 新时间序列；
- 开发者未见；
- 保留原始时间和传感器链。

## 8. Review Governance

必须区分：

```text
DRAFT
INDEPENDENT_REVIEW
ADJUDICATED
```

当前 Review A 已经进入远端文档，因此状态必须如实写：

```text
REVIEW_A_EXPOSURE=PUBLIC_REPO_DISCLOSED
```

以后不得再宣称 Review A 未公开。

Reviewer B 若要保持独立：

```text
REVIEW_B_REPO_ACCESS=NO
REVIEW_B_REVIEW_A_ACCESS=NO
```

## 9. Holdout 治理

旧 weak holdout：

- 只能做历史诊断；
- 不再承担商业盲测；
- 视觉暴露必须永久登记；
- 不得反复调参后继续称 sealed。

最终商业验证：

```text
NEW_GOLDEN
+
NEW_VESSEL
+
NEVER_SEEN_SEQUENCE
```

## 10. Ground Truth 隔离

Oracle ROI / Golden edge 只能进入：

```text
scoring/
oracle/
validation/
```

不得进入：

```text
runtime proposal
product config
training negative mining
target vessel seed
```

任何 GT 泄漏都必须记录。

## 当前输入适配与离线文件

正式 IO 支持见[ROS2 现场说明](02_ROS2现场一键识别运行说明.md)。`io/pcd_source.py` 支持 binary/scalar ASCII，保留 FLOAT32/FLOAT64 XYZ 和源 intensity 精度；`io/pointcloud2_codec.py` 独立解析 ROS2 布局。`binary_compressed` 明确拒绝，转换须记录原始 SHA、转换工具、布局和逐点 parity。原始文件不可覆盖。

输入同时保存原始 wire/file SHA 与有序、规范化 XYZ/intensity 的 semantic SHA。相同 XYZ 不代表相同消息身份；来源、frame_id、时间戳和字段布局必须保留。`SceneEvidenceContext` 固定一次 B1 点归属，生产/比较分支复用同一身份，不重新解释船体归属。运行时不加载标注；历史 PCL 零尾字节例外单列在 `config/pcd_padding_contracts.json`，只含既有文件 SHA/字节计数授权，不包含几何或 GT。

正式结果使用 `config/hatch_once.schema.json`：四份文件原子落盘，可选 NPZ 快照；失败只写 `failure_*/failure.json`。结果记录 Git SHA、源码摘要、工作树状态、配置 SHA、数值库版本、QoS、各阶段耗时、逐船/仓/边诊断。`review_coverage_boundary_xy` 是不确定性复核范围，不能当作观察到的钢边。

独立精度标注采用 `config/hatch_golden.schema.json`，必须绑定原始 PCD SHA、坐标系、标注版本、四边内法向、可见性和忽略段。`ADJUDICATED` 至少两个不同 reviewer；DRAFT 数值结果不算正式验收证据。`evaluation/hatch_precision.py` 只在离线评分入口读取标注。当前 `hatch_golden_registry.json` 为 DATA_PENDING，不含虚构钢边。

人工确认的未开舱船可登记为本轮开舱评估范围外，不依靠文件名猜测；不将未决候选记为有效开口，不把范围说明作为 runtime seed、评分输入或钢边 GT。

当前场景与去重元数据继续保留在 `ship_perception/datasets/`；已有小型合成测试夹具按清单保留，不把客户数据伪装成夹具。推断/观测/历史身份按[架构](00_系统架构与技术路线.md)分开，失败及暴露记录不得删除。
