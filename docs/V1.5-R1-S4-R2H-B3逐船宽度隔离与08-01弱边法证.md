## 第一处分叉与根因边界

R2F 时 H000、H001 的 V1 同为约 17.055 m；V0 却分别为 2.010 和 3.975 m，**宽差在 R2F proposal/side-role 阶段已产生**，约 1.965 m。H001 V0 是有实测结构/栅格支持但 `INTERIOR_HIGH_OR_CARGO`、非 canonical 的 `REVIEW_REQUIRED_RECTANGLE` 边。R2F 的四强边与远侧 return gate 能让这种角色歧义边保留为完整审查矩形。R2G 没有把它提升为确定钢边：H001 V0 在 4.07 与 4.86 两组 mode 间冲突，回退至原 3.975 m；H000 V0 同样多模式且 raw continuous 证据不足。R2G 对 H001 V1 的 +0.262 m 有多段证据，宽差因此变为约 1.703 m。

算法上可证实的根因是：**两个 R2F V0 proposal 落在不同 rho/物理角色证据上，旧 R2G 的单一 median/MAD 曾可把持续的第二组 mode 仍标为 confident；而 08-01 当时 width target 本来就是 `None`，跨舱宽度先验不是本景宽差来源。** 目前无法凭无标签单帧证明 H000 V0、H001 V0 哪一条是真实 opening inner side，也无法判定 15.04 m、13.34 m 哪个是实船真宽；物理结论为 `UNRESOLVED`。

B2 与旧框的空间关联是近似的：H000、H001 的 IoU 分别约 0.66、0.63。B2 局部轴与 R2G 略有角差，且 B2 候选边不与旧框四边一一重合；B2 provider ID 只能说明附近有 BEV/Raw3D 结构，**不能直接替代 R2G 当前 side 的 raw evidence**。R2G `_mode_profile` 仍按当前 Hatch 的沿线 span 取样，邻舱非相交区间的线不会为本边贡献覆盖；共享横梁上的实测结构允许被两个相邻开口共同审查，但不生成缺失边。

## B3 修改

1. `_ship_width_consensus()` 只接受显式 `vessel_hypothesis_id`，仅由同一 ID 的强边形成目标。旧 R2F 未携带 Vessel ID，故其宽度只作诊断，不能偷偷跨船形成 prior。双船同宽、异宽、平行及近邻测试均验证隔离。
2. 四边联合选择先按本 Hatch 的 role、Raw3D/RawXYZ coverage、opening 和 uncertainty 排序。仅当最优候选有**相同本地证据向量**、至少两个不同实测宽度 mode 时，同船 width target 才可作为最后的平分项；未实测 mode 不能被先验创造。每个 Hatch 记录 `width_prior_used` 和用途。
3. 多段 rho 以锚定式聚类检查持续的平行 mode，避免小间距样本链把两条物理边并成一条。两组各达到既有 `profile_min_sections` 且中位 rho 相隔超过既有 `corner_join_m` 时，`mode_conflict=true`、`confident=false`，保留 R2F 边。H001 V0 历史 +0.86 m 跳边和 H000 V0 链式合并有合成回归。
4. `evidence_only_width_m` 仅在 V0/V1 均为无冲突、RawXYZ 连续测得、经多段精修的 INNER_EDGE 时输出。08-01 两个值均为 `UNRESOLVED_SIDE_EVIDENCE`，不以几何或等宽补值。
