## 0. 本版最终目标

V1.4 只解决一个完整问题：

> **从现有 M0 数学/Replay 基座出发，真正接入点云配准，建立 Tracking Reference Map 和 Track-and-Map 主链，使合成船体在 World 中运动时，在 Ship Frame 内保持稳定。**

完成后，G5 不再只是 `HARNESS_ONLY`，而应具备真实配准能力：

```text
Synthetic LiDAR / static PCD
        ↓
Preprocess
        ↓
RegistrationBackend
        ↓
GICP / VGICP
        ↓
T_world_ship
        ↓
Transform to Ship Frame
        ↓
Tracking Reference Map
        ↓
Track-and-Map
        ↓
Pose / quality / timing output
```

本版是后续舱口 Polygon、实时 EKF、重定位和控制先验地图的地基。

# 3. small_gicp 集成

## 3.1 依赖原则

正式接入 `small_gicp`，但必须：

- 固定明确 tag/commit，不使用浮动 `master/main`；
- 记录版本/commit 与许可证信息；
- Ubuntu20 / GCC9 / CMake3.16 可构建；
- 优先使用 small_gicp 的 core Eigen/vector 路径；
- **核心配准接口不得依赖 small_gicp 的 PCL wrapper**；
- PCL 继续主要负责 PCD I/O 与现有几何工具；
- 保留 PCL GICP 作为 benchmark/fallback，不让它污染核心接口。

如果依赖需要 FetchContent/submodule/vendor，选择最有利于 Ubuntu20 可复现构建的方式，并固定版本。

# 4. 配准抽象层

新增稳定的配准接口，后续 EKF、重定位和真实 LiDAR 都只依赖这个接口。

建议数据结构：

```cpp
enum class RegistrationMethod {
    GICP,
    VGICP,
    PCL_GICP
};

struct RegistrationRequest {
    LocalPointCloud source;
    LocalPointCloud target;
    Eigen::Isometry3d initial_guess;
    RegistrationMethod method;
};

struct RegistrationResult {
    Eigen::Isometry3d T_target_source;
    Eigen::Matrix<double, 6, 6> H;

    double rmse;
    double overlap_ratio;
    double fitness_score;
    double elapsed_ms;

    int source_points;
    int target_points;
    int iterations;

    bool converged;
    bool valid;
};
```

允许根据现有代码风格微调，但必须保持：

```text
核心接口不泄漏 PCL 类型
T_A_B 约定不变
位姿/矩阵用 double
点云使用局部 float
结果带质量与时序信息
失败时 fail-closed
```

至少实现：

```text
RegistrationBackend
SmallGicpBackend
PclGicpBackend（若成本合理）
```

# 6. Tracking Reference Map

这是 V1.4 的第二个核心。

新增独立于 Canonical Control Model 的：

```text
TrackingReferenceMap
```

用途仅为：

```text
scan-to-model registration
```

不要把它做成控制地图。

第一版允许使用 Gaussian/Voxel map 或与 small_gicp scan-to-model 兼容的内部表示。

至少具备：

```text
Initialize()
BuildFromCloud()
GetRegistrationTarget()
InsertCandidate()
PromoteStablePoints()
Reset()
GetStatistics()
```

第一版 promotion 规则采用保守策略：

```text
高 pose 置信
+
连续多帧一致
+
低配准残差
+
非明显 transient
→ 才进入正式 tracking map
```

如果当前没有完整 dynamic semantic 模块，允许先使用：

```text
residual gate
spatial consistency
basic ROI
```

不得为了追求“智能”提前引入 PTv3。

---

# 7. Track-and-Map 主链

建立第一条真正端到端的跟踪链：

```text
Frame 0
↓
建立 provisional Ship Frame
↓
建立 Tracking Reference Map

Frame N
↓
上一帧 pose 作为 initial guess
↓
当前帧 → Tracking Reference Map
↓
GICP / VGICP
↓
得到 T_world_ship(N)
↓
当前帧转换到 Ship Frame
↓
更新 tracking map candidate
↓
符合 promotion 条件后写入
```

本版只需要实现稳定的刚体 Track-and-Map。

**本版不实现完整 ES-EKF。**

允许用：

```text
上一帧 pose
或
简单恒位姿/恒速度预测接口占位
```

作为 initial guess。

真正的 ES-EKF、observability 决策和 covariance calibration 留到下一版实时稳健跟踪。

# 17. V1.4 之后的版本路线

