## 0. 最终定调

本阶段交付不是“一张彩色点云”，而是：

> **实时建立并维护一个随船运动、在 Ship Frame 内稳定、带置信度、证据来源、版本号和有效性状态，可直接服务自动抓取与防碰撞的船舶控制先验模型。**

彩色点云只是可视化结果；后续规划模块消费 Versioned Control Prior，PLC 只消费缩减后的安全状态和目标指令。

开发与验证职责固定为：

- **Windows 桌面版 Codex：IMPLEMENTATION OWNER**
- **Ubuntu 20.04 ClaudeCLI：BUILD / TEST / FORENSIC VALIDATION OWNER**
- **Git：唯一交接介质**
- **现场真实双雷达 + PLC 数据：最终 SITE 验收依据**

# 1. 当前数据资产与限制

现有 `hold_detector/` 与数据资产保持只读：

- 约 13~16 份静态整船 PCD；
- PCD 为纯 XYZ，无 RGB、intensity、帧时间戳、per-point time；
- 23 份舱口矩形标注；
- 无 `.bag/.mcap/.db3`；
- 无连续船体漂移序列；
- 无双雷达原始分离帧；
- 无 PLC 编码器时间序列；
- 无真实动态 Pose GT；
- `output*.tar.xz` 仅为历史推理渲染产物。

因此：

- **M2 静态几何分割、舱口边界、Polygon、15 cm 级离线研发：现有数据可支撑。**
- **M0/M1/M3 的同步、双雷达融合、deskew、实时跟踪：现有数据不足，先以 synthetic replay 验证。**
- synthetic replay **不能替代 SITE 验收**。

# 2. Ubuntu 20.04 环境冻结

## 2.1 唯一目标系统

从本版开始，当前阶段所有正式文档、构建脚本、依赖说明、验证报告统一以：

```text
Ubuntu 20.04 LTS
```

作为目标。

暂时取消：

- Ubuntu 22.04 目标；
- Ubuntu 22.04 Docker canonical lane；
- Ubuntu 22.04 兼容性要求；
- “先在 20.04 验证、最终 22.04 才算正式”的表述。

后续如需迁移其他系统，应单独发起环境迁移版本，不得静默改变现有基线。

## 2.2 推荐工具链基线

以 Ubuntu 20.04 默认/常见生态为兼容下限：

```text
OS              Ubuntu 20.04 LTS
Compiler        GCC/G++ 9 系列为基线，C++17
CMake           3.16 级别为兼容基线
Eigen           系统可用版本，实际版本写入验证报告
PCL             Ubuntu 20.04 系统版本为兼容基线
Python          3.8（仅工具/评估脚本）
Git             系统版本
```

原则：

1. 产品核心使用 C++17。
2. 不要求 Windows 直接构建生产二进制。
3. 不使用只在更新发行版存在的 CMake/GCC 特性。
4. 所有真实门禁以 Ubuntu 20.04 clean build 为准。

## 2.3 small_gicp 与 PCL 的兼容策略

为避免 Ubuntu 20.04 上 PCL 版本差异影响配准核心：

- PCL 主要负责 PCD I/O、必要几何工具；
- small_gicp 优先使用其核心 Eigen/vector 接口；
- **不要把产品配准核心强绑定到 small_gicp 的 PCL wrapper**；
- 如 small_gicp 某版本与系统 PCL wrapper 不兼容，不能通过升级整个 OS 解决，应走内部点类型适配；
- 保留 PCL GICP 作为基准/回退实现，但不与 small_gicp 耦合。

# 3. 不可变架构决策

以下架构继续冻结，不因 Windows/Ubuntu 双环境而改变。

## 3.1 坐标系

统一记号：

```text
T_A_B = 把 B 坐标中的点变换到 A
p_A = T_A_B * p_B
```

Frame Tree：

```text
map/world ──┬── crane
            │    └── sensor_mount
            │          ├── lidar1
            │          └── lidar2
            └── ship
```

- `T_W_C(t)`：PLC/编码器提供；
- `T_C_L1` / `T_C_L2`：固定外参；
- `T_W_B(t)`：感知估计；
- 所有变换与协方差使用 double；
- 点云只用局部 float32；
- 落盘和消息带 `local_origin_world`。

## 3.2 Canonical Ship Frame

固定：

- `B.x` = 船艏方向；
- `B.y` = 左舷方向；
- `B.z` = 参考甲板法向向上；
- deck datum 约为 `z=0`；
- 原点位于 hatch-row 几何中心附近；
- 首次由主轴 + 泊位方向 + 操作员确认艏向解除 180° 歧义；
- Canonical Model 人工确认后，Ship Frame 原点和轴向永久冻结；
- 如必须改变 Frame，必须生成新 Model Version。

## 3.3 地图

正式控制地图：

1. `Surface Layer`：甲板 + 料面 + 可见舱底，2.5D；
2. `Structural Primitive Layer`：围板/舱壁/横梁/船舷；
3. `Sparse Residual Occupancy Layer`：斜撑、悬空、未知残差。

另设：

- `Tracking Reference Map`：专门服务 GICP/VGICP；
- `Canonical Control Model`：人工确认后 LOCKED；
- `Structural Evidence Cache`：运行中可更新；
- `Cargo Map`：快速更新。

底层原则：

```text
unknown != free
```

## 3.4 Tracking

正常链：

```text
Registration Mask
→ GICP/VGICP
→ Observability
→ Registration Covariance
→ SE(3) Error-State EKF
→ T_world_ship + covariance
```

丢失链：

```text
Feature / structural correspondences
→ TEASER++
→ topology / berth / continuity validation
→ GICP refinement
→ TRACKING
```

TEASER++ 成功不等于允许直接恢复 TRACKING。

## 3.5 Geometry First, AI Second

V1 安全关键链不依赖深度学习。

Phase 2 可加入 PTv3 自训练模型，用于：

- 逐点语义先验；
- 动态/暂态点辅助剔除；
- 复杂结构弱几何区域辅助分类。

最终安全边界必须经过几何验证。

# 4. 时间与 deskew

## 4.1 时间同步

分别做预算：

- LiDAR1 ↔ LiDAR2；
- LiDAR ↔ PLC encoder。

不预设 NTP 为同步方案。

优先级：

```text
硬件同步 / PTP / PPS
>
经验证的软件同步
```

NTP 只可做主机日志时钟。

SITE 需实测：

- offset；
- jitter；
- drift。

## 4.2 TimedPoint

算法内部只认统一格式：

```cpp
struct TimedPoint {
  Eigen::Vector3f xyz;
  float intensity;
  int64_t time_offset_ns;
  uint16_t lidar_id;
};
```

## 4.3 两阶段 deskew

Fast：

- crane/sensor motion compensation；
- 追求实时。

Map Update：

- 使用相邻 ship pose；
- SE(3) 插值；
- 延后一帧修正进入地图的数据。

不做完整 continuous-time SLAM。

# 5. 不确定度与安全

## 5.1 Observability

- 旋转 DOF 用 `L_char` 映射到位移量纲；
- 输出 per-DOF 可观性；
- 平甲板不得因总 residual 小而误报 TRACKING；
- 弱方向降低测量更新并扩大 covariance。

## 5.2 Registration Covariance

起始形式：

```text
Sigma_reg ≈ sigma_r^2 * H^-1
```

但必须：

- 用鲁棒残差尺度；
- 做归一化；
- synthetic replay 校准；
- NEES 一致性检验；
- 禁止将未经校准的 `H^-1` 宣称为真实协方差。

## 5.3 动态安全边界

控制安全边界来源：

```text
机械安全距离
+ 边界测量不确定度
+ 位姿协方差
+ 延迟
+ 标定不确定度
+ 时间同步不确定度
+ unknown exclusion
```

安全 margin 是边方向相关的，不是固定统一 inward offset。

# 8. Gate 分级

当前真实数据不足，因此每个 Gate 必须区分：

```text
PASS_SYNTHETIC
PASS_LAB
PASS_SITE
SITE_PENDING
FAIL
```

当前可离线放行：

| Gate | 当前要求 |
|---|---|
| G1 Transform | PASS_LAB |
| G2 Timestamp normalization | PASS_SYNTHETIC，SITE_PENDING |
| G3 Crane deskew | PASS_SYNTHETIC，SITE_PENDING |
| G4 Dual-LiDAR alignment | PASS_SYNTHETIC，SITE_PENDING |
| G5 Known-SE(3) | PASS_LAB |
| G6 Float precision | PASS_LAB |
| G7 Latency | PASS_LAB_LOCAL，SITE_PENDING |

因此：

```text
M0_CODE=PASS
M0_SYNTHETIC=PASS
M0_LINUX20_BUILD=PASS
M0_SITE=PENDING
```

即可进入 M1 synthetic / M2 offline 研发。

但是不得启用真实自动控制，也不得宣称 M0/M1/M3 现场验收完成，直到真实数据 Gate 达到 PASS_SITE。

1. Transform convention；
2. Timestamp normalization；
3. Crane-motion deskew synthetic；
4. Dual-LiDAR static alignment synthetic；

# 13. 确定性模式

`EVALUATION_MODE`：

- 单线程；
- 固定随机种子；
- 固定输入顺序；
- 不丢帧；
- 参考实现。

`REALTIME_MODE`：

- 并行；
- bounded queue；
- latest frame wins；
- 允许微小浮点差异。

回归按容差和状态序列，不要求 bit-exact。
