## 产品边界

`ship_structure` 只依赖 Eigen、标准库及私有 small_gicp 搜索封装。PCL 文件加载在独立 I/O target；V1.4 tracking 在独立适配 target。第三方源码、V1.4 算法与配置保持冻结，`tools/verify_v14_frozen.py` 从固定 BASE_SHA 读取权威内容。

离线输入只有 XYZ。`OfflineShipFrameProvider` 生成并比较平面、法向和 ROI 假设，可信 Deck 经过精化后决定最终 Z；ALIGNED/RAW 不改变这一要求。方向、Deck 或竞争解不能消歧时返回未解析状态。原始标注、评分标签和文件名不进入产品。

生产输入是 `ShipFrameCloud`。`ShipFrameAccumulator` 复用 `prepare_observation()`，以有效估计 `T_B_C` 变换正常传感器返回；动态点不会被 GT 标签移除。重复帧、非法矩阵、超容量与整个帧转换失败均在提交累积云前拒绝。该路径不重新调用离线坐标初始化。

## 三维结构证据

L0 高度网格只提出候选。原始三维邻域估计 normals，结构面直接在三维做稳健拟合，再与 Deck datum 求交。倾斜立面不能先压成二维细线，否则投影宽度会使有效支持消失。

顶视路径比较局部甲板平台、下降段和内部返回。平坦甲板支持必须到达被选转折；不同长度拟合窗口的 Deck 交点必须稳定。跨越可见围板顶部的插值不能作为 opening-side 边界。平滑或竞争转折保留 PARTIAL，不能以高度阈值选出的等高线冒充 observed 内缘。

边界合并保留支持区间和缺口。拓扑没有固定四边形模板；可确定闭合且满足实测覆盖的候选才输出完整多边形。端点只有实测边交会等终止证据时才 bounded，否则 uncertainty 为 null。所有不确定性都是几何代理，不是已标定协方差。

## 产物与追溯

模型契约为 `config/v15_model.schema.json`；`tools/v15_artifacts.py` 同时检查 SE(3)、有限值、支持区间、证据计数、端点与完整状态。输出模型 JSON、Deck、polygon、boundary、primitive、timing、metadata、报告及摘要索引。

`debug_semantics.ply` 显示候选边界；`colored_debug_cloud.ply` 将运行时原始点变换到输出坐标后按与边界证据的邻近关系着色。绿色为 observed 支持附近的点，橙色为 inferred 附近的点，灰色为其他点。颜色只是可视化覆盖层，不是逐点语义真值。产品 metadata 不包含 annotation hash；评分通道另存标注追溯。

V1.5 配置哈希使用排序键和无多余空白的规范 JSON 字节；CRLF/LF 与格式化不会改变参数身份。原始文件 hash 可另存，不能与参数身份混淆。

`v15_holdout_ledger.py` 区分文件编码审计与算法评分，以摘要链检测记录改写；首次评分后算法、配置或数据契约改变则永久标记污染。仅 Git SHA 因文档变化不自动等于算法改变。
