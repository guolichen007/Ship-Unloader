## 目标与输入

本轮在 `r1_static` 离线研究链中，将已执行 profile 的每一个 break/face 原始 XY 观测纳入舱口拓扑求解。输入是 Development 原始 PCD、冻结的 `baseline_004` Height opening、当前扫描的 S4-R1 PlaneFamily/profile 结果。附件 `r1_structural_lines.zip` 中六份 `structural_lines.ply` 是**由既有结构线生成的稀疏可视化点**，只用于逐边空间复核和绘图，不能代替原始 PCD 或作为独立钢边真值。

本地 Git 仅有 S4-R1 分支基线；附件提及的远端 S4-R2 提交不在本地对象中，SSH 主机密钥文件受权限限制、HTTPS 连接不可达。本轮实现基于本地 S4-R1 和附件产物，不声称已经集成到远端 S4-R2 代码。

算法不读取 Hatch GT、场景预期舱数、固定舱口尺寸、历史船模型或 sealed 标注。Height box 只提供空间种子；最终确认的 `polygon_xy` 必须由四个 Raw3D 观测边、各边覆盖率和角端观测共同支持。证据不完整时只保留 `hypothesis_corners_xy` 作为待审查假设，`polygon_xy=null`。

## 实现

- `family_reference.py` 为每段保存原始剖面点和 segment 方向、法向、起止点；已存的点不会因为局部 `_fit_line` 失败而丢弃。
- `boundary_topology.py` 给每个 break/face 点分配稳定 observation ID，并记录来源 segment、node、family 和 `USED_IN_BOUNDARY_LINE` 或结构化拒绝原因。
- 当前船主轴使用四倍角的近正交共识，每个 Height node 的总投票权封顶。`INTERIOR_SURFACE`、`ROLE_AMBIGUOUS_OVERFLOW` 不参与轴或边界模式。
- 每个 node 独立把同方向的原始点组投到 rho，形成边界模式；四边候选由两个 rho 对确定。边覆盖率按实际连续观测区间算，角端必须在现有 `corner_join_m + max_support_gap_m` 门内有原始点。
- PLY 解码检查格式、字段、顶点数、有限坐标；输出每边附近的 PLY 顶点数和审查 PNG。该 PLY 指标仅作可视化核对，不升级证据等级。

## 可复现命令

先将所附 ZIP 的六个 `structural_lines.ply` 解压至 `Ship-Unloader-Work/review/r1_structural_lines/`，命名为 `<scene>_structural_lines.ply`。单场景示例：

```powershell
python -m ship_perception.r1_static.boundary_topology `
  --scene 4-16 `
  --pcd Ship-Unloader-Data/legacy/hold_detector/detect/test/final_map_4_16_2d_005.pcd `
  --height-root Ship-Unloader-Work/r1_heightmap/baseline_004_heightmap `
  --ply Ship-Unloader-Work/review/r1_structural_lines/4-16_structural_lines.ply `
  --output Ship-Unloader-Work/review/r1_structural_lines/4-16_raw_topology.json
```

亦可用 `--s4r1-root Ship-Unloader-Work/r1_family_reference/baseline_008_s4r1` 复核旧缓存。两个来源互斥。JSON 中保留全部 observation accounting；同名 PNG 为整场景图，`_node_<id>.png` 为单 node 图。所有产物位于 `Ship-Unloader-Work/`，不提交 Git。
